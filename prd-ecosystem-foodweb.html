                  1. 개요

                  1.1 배경

                  초등 과학의 먹이 사슬·먹이 그물 수업은 대부분 "누가 누구를 먹는가"를 화살표로 잇는 활동에서 끝납니다. 시중의 카드 게임과 학습 앱도 어휘와 순서 암기에 머무는 경우가 많습니다. 그러나 이 단원의 핵심은 "한 생물이 사라지거나 늘어나면 연결된 다른 생물에게 어떤 연쇄 반응이 일어나는가"를 추론하는 시스템 사고입니다.

                  교실에서는 털실로 학생들을 연결해 한 명이 줄을 당기면 다른 학생이 흔들리는 활동(Human Food Web)이나, 포식자-피식자 카드 게임 뒤에 특정 종을 제거하는 탐구(Mystery Science)가 널리 쓰입니다. 하지만 종이와 털실로는 시간에 따른 개체 수 변화와 간접 효과(예: 뱀이 사라지면 개구리가 늘고, 그 결과 메뚜기가 줄고, 풀이 늘어남)를 눈으로 확인하기 어렵습니다.

                  이 앱은 학생을 생태계의 연쇄 반응을 추리하고 지키는 탐정단원(생태계 관리인)으로 설정하고, 다음 흐름으로 시스템 사고를 연습하게 합니다.

                  1. 생물 카드를 모아 먹이 그물을 직접 연결합니다.
                  2. 사건 카드(가뭄, 외래종 유입, 특정 종 감소 등)가 발동됩니다.
                  3. 무슨 일이 일어날지 먼저 예측합니다.
                  4. 몇 턴에 걸쳐 개체 수 막대가 변하는 시뮬레이션을 관찰합니다.
                  5. 예측과 결과를 비교하고, 화살표를 따라 "왜 그렇게 되었는지"를 설명합니다.

                  1.2 목표

                  • 교육 목표
                  • 먹이 사슬과 먹이 그물의 차이를 설명할 수 있습니다.
                  • 생산자·소비자·분해자의 역할을 알고, 화살표가 "먹히는 생물 → 먹는 생물"(에너지 이동 방향)임을 정확히 표현합니다.
                  • 한 생물의 변화가 직접 연결되지 않은 생물에게까지 영향을 준다는 것(간접 효과)을 추론합니다.
                  • 먹이 관계가 다양할수록 생태계가 변화에 덜 흔들린다(생태계 평형)는 것을 경험으로 이해합니다.
                  • 우리나라의 숲·논·갯벌 생태계와 외래종·서식지 파괴 같은 실제 환경 문제를 연결합니다.
                  • 제품 목표
                  • 40분 수업 1~2차시 안에 도입부터 성찰까지 끝낼 수 있는 흐름을 제공합니다.
                  • 설치·로그인 없이 주소 하나로 바로 실행되고, 학교 와이파이가 불안정해도 동작합니다(오프라인 지원).
                  • 사전·사후 진단 문항을 내장해 교사가 간단히 학습 효과를 확인할 수 있게 합니다.

                  1.3 차별점

                  기존 먹이 사슬 게임·활동 먹이그물 탐정단
                  먹이 관계 짝짓기, 순서 맞히기 먹이 그물 전체를 만들고 종 제거·사건 시뮬레이션이 핵심
                  정답이 하나인 퀴즈 예측 → 관찰 → 설명 순환(POE: Predict-Observe-Explain)
                  결과만 보여 줌 화살표 따라 영향이 퍼지는 과정을 애니메이션과 문장으로 설명
                  외국 생물(사자, 얼룩말) 중심 우리나라 숲·논·갯벌 생물과 실제 환경 이슈(황소개구리, 갯끈풀 등)

                  1.4 범위에서 제외하는 것 (Non-goals)

                  • 로그인, 회원가입, 학생 개인정보(이름 등) 수집, 서버 백엔드
                  • 기기 간 실시간 대전(서버 필요). 모둠 경쟁은 서버 없이 가능한 방식으로만 제공합니다(4장 F8 참고).
                  • 생성형 AI 호출(아동 대상 서비스의 안전·비용 문제로 제외). 설명 문장은 미리 작성한 템플릿으로 만듭니다.
                  • 실제 생태학 연구 수준의 정밀한 개체 수 예측. 이 앱의 시뮬레이션은 경향을 보여 주는 단순 모델입니다.
                  • 결제, 광고, 외부 분석 도구(추적 스크립트)

                  2. 사용자와 사용 시나리오

                  2.1 사용자

                  사용자 특징 필요한 것
                  학생(초4~6) 긴 글 읽기를 어려워하는 학생도 있음. 터치 조작에 익숙함. 경쟁과 수집을 좋아함 짧고 쉬운 문장, 큰 버튼, 즉각적인 피드백, 모으는 재미
                  교사(주 사용자이자 운영자) 40분 안에 수업을 끝내야 함. 기기 문제에 대응할 시간이 부족함 바로 켜지는 앱, 전자칠판용 진행 화면, 차시별 지도안, 결과 확인
                  개발자(본인) 바이브 코딩으로 개발. 콘텐츠(생물 데이터)도 직접 작성 단순한 구조, 데이터와 로직 분리, 시뮬레이션을 검증할 테스트

                  2.2 사용 환경 가정

                  • 학생 1인 1기기 또는 2인 1기기(태블릿, 크롬북). 화면 크기 10인치 안팎.
                  • 교실 앞 전자칠판(또는 프로젝터 + 교사 노트북) 1대.
                  • 학교 기기는 여러 반이 함께 쓰므로, 기기에 남는 데이터는 학생 번호(예: 5-2반 13번)만 사용합니다.

                  2.3 대표 수업 시나리오

                  6학년 2반, 과학 '생물과 환경' 단원 4~5차시. 학생 24명, 태블릿 24대, 전자칠판 1대.

                  1차시(40분): 먹이 그물 만들기 1. (5분) 교사가 전자칠판에서 앱을 열고 수업 모드를 켭니다. 학생은 태블릿에서 같은 주소를 열고 학급·번호를 입력합니다. 2. (5분) 학생이 사전 진단 5문항을 풉니다("뱀이 사라지면 개구리는 어떻게 될까요?" 등). 3. (5분) 숲 테마 튜토리얼: 카드 3장으로 먹이 사슬(풀 → 메뚜기 → 개구리)을 연결해 보고, 화살표 방향의 의미를 배웁니다. 4. (15분) 먹이 그물 만들기: 숲 생물 카드 12장을 놓고 화살표로 연결합니다. 틀린 연결은 즉시 알려 주고 힌트를 줍니다. 완성하면 새 카드를 얻습니다. 5. (10분) 교사가 전자칠판에서 대표 학생의 먹이 그물을 띄워 함께 확인하고, "먹이 사슬과 무엇이 다른가요?"를 묻습니다.

                  2차시(40분): 생태계 관리인 1. (20분) 관리인 모드: 사건 카드 "뱀이 크게 줄었어요"가 발동됩니다. 학생은 개구리·메뚜기·풀이 어떻게 될지 예측하고, 가장 큰 영향을 받을 생물을 고릅니다. 시뮬레이션을 8턴 동안 관찰하고 점수를 받습니다. 이어서 관리인 행동 카드로 생태계 균형을 되찾습니다. 2. (12분) 모둠 대항전: 교사가 전자칠판에서 논 테마 사건 카드 "황소개구리가 들어왔어요"를 띄웁니다. 6개 모둠이 토의해 예측을 고르고, 교사가 모둠별 예측을 입력한 뒤 시뮬레이션을 함께 봅니다. 점수판에 모둠 점수가 쌓입니다. 3. (8분) 사후 진단과 성찰 질문("내가 사는 동네에서 사라지면 큰일 날 생물은?")에 답합니다. 교사는 수업이 끝난 뒤 기기별 결과를 확인하거나 CSV로 모읍니다.

                  3. 전체 사용 흐름

                  [시작]  학급·번호 입력(선택) → 메인 화면
   │
   ├─ [튜토리얼]  먹이 사슬 3장 연결 → 화살표 의미 → 먹이 그물로 확장
   │
   ├─ [먹이 그물 만들기]  테마 선택(숲/논/갯벌) → 카드 배치 → 화살표 연결 → 검증 → 카드 보상
   │
   ├─ [관리인 모드(캠페인)]  테마별 5개 스테이지
   │      안정 상태 관찰 → 사건 카드 발동 → 예측 → 시뮬레이션 관찰 → 채점·설명 → 관리인 행동 → 균형 점수
   │
   ├─ [탐구 모드(자유 실험)]  아무 생물이나 없애기·늘리기·외래종 넣기 → 결과 관찰
   │
   ├─ [카드 도감]  모은 카드 보기, 생물 정보, 먹이·천적 관계
   │
   └─ [진단]  사전·사후 진단 5문항

[교사 메뉴]  수업 모드(전자칠판), 모둠 대항전 점수판, 기기별 결과 보기·CSV 내보내기, 전체 카드 잠금 해제, 설정

                  4. 기능 요구사항

                  우선순위는 P0(MVP 필수), P1(v1 포함), P2(이후 확장)로 표시합니다.

                  F1. 시작과 학생 식별 (P0)

                  ID 요구사항 우선순위
                  F1-1 시작 화면에서 학년·반·번호 입력(이름 입력란은 두지 않음). 건너뛰기 가능(손님 모드) P0
                  F1-2 같은 기기를 여러 학생이 쓰는 경우를 위해 "학생 바꾸기" 버튼과 학생별 진행 상황 분리 저장 P0
                  F1-3 진행 상황(카드, 별, 점수, 진단 결과)은 기기의 localStorage에 자동 저장 P0
                  F1-4 교사용 "이 기기 데이터 모두 지우기"(학기 말 정리용, 확인 2회) P0

                  F2. 생물 카드와 카드 도감 (P0)

                  ID 요구사항 우선순위
                  F2-1 생물 카드 구성: 그림, 이름, 역할(생산자/1차 소비자/2차 소비자/최종 소비자/분해자) 색상 띠, 사는 곳, 먹이, 천적, 한 줄 사실("고라니는 우리나라에 천적이 거의 없어요") P0
                  F2-2 역할별 색상 + 모양 아이콘을 함께 사용(색각 이상 학생 고려). 예: 생산자 초록 잎, 소비자 주황 발자국, 분해자 갈색 버섯 P0
                  F2-3 카드 획득: 튜토리얼 완료, 먹이 그물 완성, 스테이지 별 획득, 정확한 예측 연속 성공 시 보상 P0
                  F2-4 카드 도감: 테마별 수집 현황(예: 숲 9/12), 미획득 카드는 그림자로 표시 P0
                  F2-5 희귀 카드: 멸종위기종(수리부엉이, 저어새, 삵 등)과 외래종(황소개구리, 갯끈풀 등)은 특별 테두리와 "보호가 필요해요/생태계 교란 생물" 설명 P1
                  F2-6 교사 모드에서 모든 카드 잠금 해제(수업 진도에 맞춰 바로 사용) P0

                  F3. 먹이 그물 만들기 (P0)

                  6. 시뮬레이션 모델

                  6.1 설계 원칙

                  • 초등학생이 결과를 보고 "화살표를 따라가면 이해가 되는" 수준의 단순 모델을 씁니다.
                  • 기본 형태는 생태학의 로트카-볼테라(Lotka-Volterra) 포식자-피식자 모델을 단순화한 턴제 계산입니다.
                  • 화면에는 수식을 보여 주지 않습니다. 교사 가이드에만 원리를 쉬운 말로 설명합니다.

                  6.2 계산식

                  개체 수 지수를 기준값 1.0(화면 표시는 100)으로 정규화합니다. 한 턴은 작은 계산 단계 10번(dt = 0.1)으로 나누어 계산해 값이 튀지 않게 합니다.

                  생산자 i

                  변화량 = r_i × N_i × (1 − N_i / (K_i × E_i × S_i)) − Σ_j a_ij × N_i × N_j
                  • r_i: 성장률, K_i: 최대 한도, E_i: 환경 계수(가뭄·산불 시 1보다 작음), S_i: 양분 계수(분해자 상태에 따라 0.7~1.0)
                  • Σ_j: 생산자 i를 먹는 모든 소비자 j

                  소비자 j

                  변화량 = e × Σ_i a_ij × N_i × N_j  −  Σ_k a_jk × N_j × N_k  −  m_j × N_j
                  • 첫째 항: 먹이에서 얻는 성장(e: 먹이 전환 효율)
                  • 둘째 항: 천적 k에게 먹혀서 줄어듦
                  • 셋째 항: 자연 사망(m_j: 사망률)

                  분해자 d와 찌꺼기 D

                  찌꺼기 변화량 = (그 턴에 죽은 양의 합) − b × N_d × D
분해자 변화량 = e_d × b × N_d × D − m_d × N_d
양분 계수 S = 0.7 + 0.3 × min(1, N_d)
                  • 분해자가 줄면 찌꺼기가 쌓이고 양분 계수가 떨어져 생산자가 천천히 줄어듭니다.

                  공통 처리 - 모든 값은 0 이상, 상한 3.0(지수 300)으로 제한합니다. - 지수 2(0.02) 미만이 되면 0으로 만들고 "사라짐" 상태로 바꿉니다.

                  6.3 자동 보정(균형 상태 만들기)

                  생물 데이터를 작성할 때 계수를 일일이 맞추기는 어렵습니다. 그래서 모든 생물이 기준값 1.0일 때 변화량이 0이 되도록 계수를 자동으로 계산합니다.

                  1. 데이터에는 먹이 관계와 먹이 선호도(예: 뱀은 들쥐 50%, 개구리 30%, 박새 20%)만 적습니다.
                  2. 선호도에 소비자별 섭식량 c_j를 곱해 a_ij를 정합니다.
                  3. 소비자 사망률: m_j = e × Σ_i a_ij − Σ_k a_jk (균형 조건에서 역산). 값이 0 이하이면 데이터 오류로 보고 빌드 단계에서 경고합니다.
                  4. 생산자 최대 한도: K_i = 1 / (1 − Σ_j a_ij / r_i) (Σ_j a_ij < r_i 이어야 함).

                  이렇게 하면 사건이 없을 때 생태계가 저절로 균형을 유지하고, 사건이 생긴 뒤의 변화만 순수하게 관찰할 수 있습니다.

                  6.4 안정성 확보

                  로트카-볼테라 모델은 진동(늘었다 줄었다 반복)이 커질 수 있습니다. 다음 장치로 아이들이 이해하기 쉬운 변화 곡선을 만듭니다. - 포식자 간섭 항(같은 포식자끼리 경쟁)으로 진동 줄이기 - 계산 단계를 잘게 나누기(dt = 0.1) - 자동 테스트(6.6)로 테마별 안정성과 사건별 결과 방향을 검증

                  6.5 설명 문장 생성

                  매 턴 생물별로 변화량의 각 항(먹이에서 얻는 양, 천적에게 먹히는 양, 사건 효과)을 기준 상태와 비교해 가장 큰 원인을 찾고, 템플릿 문장으로 바꿉니다.

                  원인 템플릿
                  먹이 감소 "{생물}이(가) 줄었어요. 먹이인 {먹이}이(가) 줄었기 때문이에요."
                  먹이 증가 "{생물}이(가) 늘었어요. 먹이인 {먹이}이(가) 많아졌기 때문이에요."
                  천적 증가 "{생물}이(가) 줄었어요. {생물}을(를) 먹는 {천적}이(가) 늘었기 때문이에요."
                  천적 감소 "{생물}이(가) 늘었어요. {생물}을(를) 먹는 {천적}이(가) 줄었기 때문이에요."
                  먹이 여러 가지 "{생물}은(는) {먹이1}이(가) 줄었지만 {먹이2}을(를) 먹어서 크게 줄지 않았어요."
                  사건 직접 영향 "{사건} 때문에 {생물}이(가) 직접 줄었어요."
                  • 한국어 조사(이/가, 을/를, 은/는)는 받침 여부로 자동 선택합니다.
                  • 이 기록을 거꾸로 따라가면 "뱀 감소 → 개구리 증가 → 메뚜기 감소 → 풀 증가" 같은 영향 경로를 만들 수 있고, 질문 3의 정답과 화살표 빛 애니메이션에 사용합니다.

                  6.6 시뮬레이션 검증 테스트

                  테스트 기준
                  무사건 안정성 30턴 동안 모든 생물이 기준값 ±2% 안에 머묾
                  복원력 한 생물을 20% 줄인 뒤 30턴 안에 ±5% 안으로 돌아옴
                  교과서 정답 일치 "포식자 제거 → 피식자 증가", "생산자 감소 → 1차 소비자 감소" 등 교과서 핵심 관계가 모든 테마에서 성립
                  출제 품질 스테이지 질문의 정답 생물 변화율이 ±12% 밖에 있음(애매하지 않음)
                  데이터 검증 모든 소비자에게 먹이가 1개 이상, 사망률 > 0, 생산자 조건 충족

                  7. 오개념과 대응 설계

                  흔한 오개념 대응
                  화살표를 "먹는 생물 → 먹히는 생물"로 그림 방향 반대 감지 피드백(F3-4), 화살표에 "에너지가 이동해요" 빛 흐름 애니메이션
                  먹이 사슬 위쪽 생물은 아래 생물을 모두 먹는다 먹이 그물 만들기에서 잘못된 연결에 구체적 이유 제시
                  포식자가 사라지면 피식자에게는 무조건 좋다 스테이지 3~4: 피식자가 너무 늘어 먹이가 부족해지고 결국 다시 줄어드는 과정 관찰
                  한 생물의 변화는 바로 옆 생물에게만 영향을 준다 질문 1을 직접 연결되지 않은 생물 위주로 출제, 영향 경로 애니메이션
                  변화는 즉시 일어난다 턴별 재생으로 시간 지연 관찰("3턴 뒤에야 풀이 늘기 시작했어요")
                  분해자는 중요하지 않다 탐구 모드 미션 "분해자를 없애 보세요" → 찌꺼기 증가, 생산자 서서히 감소
                  시뮬레이션 결과 = 실제 자연 결과 화면에 "실제 자연은 날씨, 질병 등 더 많은 것이 영향을 줘요" 안내, 교사 가이드에 모델 한계 설명

                  8. 기술 스택

                  영역 선택 이유
                  프레임워크 React + TypeScript + Vite 바이브 코딩 자료가 많고, 타입으로 데이터 오류를 줄임
                  먹이 그물 시각화 D3.js(d3-force) + SVG 힘 기반 배치에 영양 단계별 세로 위치 힘(forceY)을 더해 "아래 생산자 → 위 최종 소비자" 층 구조 유지
                  끌어서 연결 SVG 포인터 이벤트 직접 구현 노드 13개 수준이라 별도 라이브러리 불필요. 대안: React Flow(연결 UI가 기본 제공되나 층 배치는 직접 구현)
                  개체 수 막대·그래프 CSS 막대 + 간단한 SVG 꺾은선 라이브러리 없이 충분, 애니메이션 제어 쉬움
                  상태 관리 Zustand 단순하고 코드가 짧음
                  시뮬레이션 엔진 순수 TypeScript 모듈(화면과 분리) 단위 테스트(Vitest)로 검증, 모둠 대항전 결정론 보장
                  저장 localStorage 학생 번호별 진행 상황, 수 KB 수준
                  오프라인 PWA(vite-plugin-pwa) 학교 와이파이 불안정 대응, 첫 접속 후 오프라인 실행
                  효과음 Web Audio(짧은 효과음 몇 개) 교실 기본값은 소리 끔
                  QR(P2) qrcode 생성 + 카메라 인식 라이브러리 서버 없이 결과 수집
                  배포 GitHub Pages 무료, 주소 하나로 배포
                  테스트 Vitest(엔진·데이터), Playwright(주요 화면 흐름)

                  교사 수업 모드, 모둠 대항전, 기기별 결과, CSV 내보내기, 카드 잠금 해제, 데이터 지우기
                  모둠 대항전(전자칠판) 큰 사건 카드, 타이머, 모둠별 예측 입력 버튼, 점수판
                  • 기본 방향은 가로 화면(태블릿·전자칠판). 세로 화면에서는 막대와 그물을 위아래로 배치합니다.

                  11. 비기능 요구사항

                  성능 첫 화면 3초 이내(학교 와이파이 기준), 시뮬레이션 1턴 재생 중 끊김 없음(초당 30프레임 이상)
                  오프라인 한 번 접속한 뒤에는 인터넷 없이 모든 기능 사용 가능
                  터치 버튼·카드 최소 48×48px, 카드끼리 붙어 있어도 연결 실수 줄이도록 자석 효과(가까운 카드에 자동으로 붙음)
                  글 초4 수준 어휘, 한 문장 25자 안팎, 어려운 낱말(생산자 등)은 탭하면 뜻 풀이
                  접근성 색 + 아이콘 + 글자로 증감 표시(▲ 늘어요/▼ 줄어요), 고대비 모드, 글자 크기 2단계
                  개인정보 이름·사진 등 개인정보 수집 없음, 외부 전송 없음, 추적 스크립트 없음
                  소리 기본값 끔(교실), 켜면 짧은 효과음만
                  수업 시간 한 판(관리인 라운드) 5~8분, 먹이 그물 만들기 10~15분

                  12. 개발 단계 (마일스톤)

                  M1. 데이터와 시뮬레이션 엔진 (화면 없음)

                  • 숲 테마 데이터 작성, 자동 보정·턴 계산·사건 효과 구현
                  • 6.6 검증 테스트 통과, 명령줄에서 사건별 결과 표 출력
                  • 완료 기준: "뱀 감소 → 개구리 증가 → 메뚜기 감소 → 풀 증가"가 테스트로 확인됨

                  M2. 먹이 그물 만들기

                  • D3 층 배치 캔버스, 끌어서 연결, 즉시 판정·힌트, 자동 정렬
                  • 튜토리얼(먹이 사슬 3장)
                  • 완료 기준: 태블릿에서 숲 먹이 그물을 10분 안에 완성할 수 있음

                  M3. 관리인 모드(핵심 게임 루프)

                  • 사건 발동 → 예측 → 시뮬레이션 재생 → 채점·설명 → 관리인 행동 → 별
                  • 설명 문장 생성, 영향 경로 애니메이션
                  • 숲 5개 스테이지
                  • 완료 기준: 숲 테마로 한 차시 수업 진행 가능

                  M4. 논·갯벌 콘텐츠와 카드 수집

                  • 논·갯벌 데이터·사건·스테이지 작성, 테마 고유 사건(농약, 기름 유출, 갯끈풀 등)
                  • 카드 도감과 보상, 탐구 모드
                  • 과학 교사 콘텐츠 검토 1차
                  • 완료 기준: 세 테마 모두 검증 테스트 통과, 콘텐츠 검토 의견 반영

                  M5. 교실 기능

                  • 학생 번호 관리, 사전·사후 진단, 교사 결과 화면·CSV
                  • 모둠 대항전(전자칠판 진행형, 도전 코드형)
                  • PWA 오프라인, 교사 가이드
                  • 완료 기준: 실제 교실 기기(태블릿 + 전자칠판)에서 2차시 수업 리허설 성공

                  M6. 파일럿 수업과 개선

                  • 1~2개 학급에서 2차시 파일럿, 사전·사후 진단 비교
                  • 학생 관찰 기록과 교사 의견으로 난이도·문장 수정
                  • 먹이 사슬 vs 먹이 그물 비교 실험(F7-4), 실험 기록장 등 P1 기능 추가

                  13. 위험 요소와 대응

                  위험 영향 대응
                  시뮬레이션 결과가 직관이나 교과서와 다름 학생 혼란, 교사 신뢰 하락 자동 보정 + 교과서 정답 일치 테스트, 애매한 문제 자동 제외, 결과마다 설명 문장 제공
                  진동이 커서 결과가 이상하게 출렁임 해석 어려움 포식자 간섭 항, 작은 계산 단계, 안정성 테스트
                  생물 관계 데이터 오류 잘못된 개념 학습 출처 기록, 과학 교사 검토, 대표 관계만 사용
                  세 테마 콘텐츠 작성량이 많음 일정 지연 데이터 형식을 먼저 확정하고 숲으로 엔진 검증 후 논·갯벌은 데이터만 추가, 데이터 무결성 테스트 자동화
                  먹이 그물이 복잡해 화면이 어지러움 저학년·느린 학습자 어려움 테마당 13종 이하, 분해자 연결 숨김, 층 배치, 쉬움 단계(생물 8종) 제공
                  저가 태블릿 성능 부족 끊김 SVG 노드 20개 이하, 애니메이션 단순화, 실제 학교 기기로 조기 테스트
                  공용 기기에 학생 기록이 섞임 결과 신뢰도 저하 학생 바꾸기 버튼, 수업 시작 시 번호 확인, 교사의 데이터 지우기 기능
                  경쟁이 과열되어 추론보다 찍기에 집중 학습 효과 저하 질문 3(이유)에 높은 배점, 모둠 토의 시간 확보, 오답에도 설명으로 배움 제공
                  효과 검증 연구 부족(근거 강도 ★☆☆) 효과 불확실 사전·사후 진단 내장, 파일럿에서 간단한 효과 측정

                  14. 성공 지표

                  지표 목표(파일럿 기준) 측정 방법
                  간접 효과 문항 정답률 상승 사전 대비 사후 +20%p 이상 진단 4번 문항
                  이유 설명 수준 사후 서술형에서 2단계 이상 영향 경로를 쓴 학생 비율 50% 이상 진단 5번 문항, 교사 채점
                  화살표 방향 오류 먹이 그물 만들기 마지막 시도에서 방향 오류 10% 이하 앱 기록
                  수업 내 완료율 1차시 먹이 그물 완성 90% 이상 앱 기록
                  예측 정답률 변화 첫 스테이지 대비 마지막 스테이지 정답률 상승 앱 기록
                  교사 만족도 "다시 수업에 쓰겠다" 응답 파일럿 교사 면담

                  15. 결정된 사항과 남은 확인 사항

                  15.1 결정된 사항 (v0.2)

                  • 앱 이름: 먹이그물 탐정단(Web Rangers)
                  • 사용 환경: 교실 수업 중심(태블릿·크롬북 + 전자칠판)
                  • 플레이 방식: 1인 관리인 모드 + 모둠 대항전(실시간 서버 없이 전자칠판 진행형·도전 코드형)
                  • 데이터: 로그인 없이 기기에 저장, 학생은 학년·반·번호만 입력, 결과는 교사 화면과 CSV로 확인
                  • MVP 테마: 숲·논·갯벌 세 가지 모두
                  • 생성형 AI는 사용하지 않음, 설명 문장은 템플릿으로 생성

                  15.2 확인이 필요한 사항

                  1. 교육과정 연결: 수업에 쓸 교과서(2022 개정 교육과정 적용 학년·출판사)와 해당 차시를 알려 주시면, 생물 목록과 진단 문항을 교과서 예시에 맞추겠습니다.
                  2. 학교 기기 환경: 실제로 쓸 태블릿 기종(갤럭시 탭, 아이패드, 크롬북)과 전자칠판 브라우저를 확인하고 싶습니다.
                  3. 그림 제작 방식: 직접 그리기, 이모지·아이콘 활용, AI 이미지 생성 중 어떤 방식을 선호하시나요? (생물 약 40종 + 사건·행동 카드 약 30장 필요)
                  4. 난이도 단계: 4학년도 쓸 수 있게 "쉬움(생물 8종)" 단계를 MVP에 넣을지, 5~6학년 기준으로만 만들지 정해야 합니다.
                  5. 콘텐츠 검토자: 생물 관계를 검토해 줄 과학 교사나 전문가가 있는지 확인이 필요합니다.
                  6. 모둠 대항전 우선순위: 전자칠판 진행형과 도전 코드형 중 먼저 만들 방식을 정하면 M5 범위를 줄일 수 있습니다.
