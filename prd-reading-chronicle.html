              앱 이름

              확정한 이름

              나이테 책장 (Ringshelf): 해마다 한 겹씩 쌓이는 나의 독서

              • 의미: 나무가 해마다 나이테를 한 겹씩 두르듯, 1년에 한 칸씩 책장이 늘어납니다. "연도별 독서 연대기"라는 핵심 개념을 그대로 담았습니다.
              • 표기 규칙: 한글 화면에서는 "나이테 책장", 영문·코드·주소에서는 "Ringshelf"(소문자 ringshelf)를 씁니다.
              • 아이콘 방향: 동심원 나이테 위에 색색의 책등이 방사형으로 꽂힌 모양, 원목 갈색(#8A5A2B) 기본
              • 코드 식별자: IndexedDB 이름 ringshelf, 백업 파일 ringshelf-backup-YYYYMMDD.json, 프록시 Worker 이름 ringshelf-proxy

              1. 개요

              1.1 배경

              독서 기록 앱은 많지만, 대부분 목록과 숫자(권수, 별점) 중심입니다. 몇 년치 기록이 쌓여도 "그해에 나는 어떤 책을 읽었나"를 한눈에 느끼기 어렵습니다. 실제 책장 앞에 서면 책 두께와 색깔만으로도 기억이 되살아나는데, 디지털 기록에는 그런 감각이 없습니다.

              이 앱은 다음 세 가지를 결합합니다.

              1. 책장 시각화: 쪽수로 책등 두께를, 표지에서 뽑은 색과 분야별 무늬로 책등을 자동으로 만들어 연도별 책장에 꽂아 보여 줍니다.
              2. 연도 비교 분석: 권수, 쪽수, 분야 비중, 월별 추이를 여러 해에 걸쳐 겹쳐 봅니다.
              3. 회고 의식: "그해의 책"을 고르고 한 줄 회고를 남기며, 연말 회고 카드를 이미지로 내보내 공유합니다.

              1.2 목표

              • 해마다 읽은 책을 한 칸의 책장으로 보여 주어, 독서 이력을 시각적으로 기억하게 합니다.
              • 연도 사이의 변화(많이 읽은 해, 분야가 바뀐 해, 독서가 몰린 달)를 숫자와 그래프로 비교합니다.
              • 책 한 권 등록에 10초 이내가 걸리도록 ISBN·제목 검색으로 정보를 자동 입력합니다.
              • 기존 기록(엑셀, 다른 앱)을 CSV로 가져와 첫날부터 여러 해의 책장을 채울 수 있게 합니다.
              • 서버 없이 기기 안에만 저장해 개인정보 부담을 없애고, 오프라인에서도 동작하게 합니다.

              1.3 범위에서 제외하는 것 (Non-goals)

              • 로그인, 회원가입, 클라우드 동기화, 여러 기기 간 실시간 동기화 (JSON 백업으로 대체)
              • 친구 팔로우, 피드, 댓글 같은 소셜 기능
              • 인용문·독서 노트 중심 기능 (아이디어 4-1 원안의 인용문 수집은 P2로 미룸)
              • 전자책 뷰어, 도서 구매·대여 연동
              • AI 추천 기능 (v1 이후 검토)

              2. 사용자와 사용 시나리오

              2.1 주 사용자

              • 1년에 10~100권을 읽고, 읽은 책을 남겨 두고 싶은 개인 독자
              • 연말에 "올해의 책"을 정리해 블로그·SNS에 올리는 사람
              • 이미 엑셀이나 다른 앱에 몇 년치 기록이 있어 옮겨 오고 싶은 사람

              2.2 대표 시나리오

              시나리오 A: 책 한 권 추가 (일상) 1. 책을 다 읽고 앱을 엽니다. + 버튼을 누르고 제목 일부를 입력합니다. 2. 알라딘 검색 결과에서 책을 고르면 제목, 저자, 출판사, 쪽수, 분야, 표지가 채워집니다. 3. 다 읽은 날짜와 별점, 한 줄 메모를 넣고 저장합니다. 4. 올해 책장 맨 끝에 표지색 책등이 "쏙" 꽂히는 애니메이션이 나옵니다.

              시나리오 B: 과거 기록 옮기기 (첫 사용) 1. 엑셀에 정리해 둔 2019~2025년 독서 목록을 CSV로 저장합니다. 2. 앱에서 CSV를 불러오고, 열(제목, 저자, ISBN, 완독일)을 앱 항목에 맞춥니다. 3. 앱이 ISBN 또는 제목으로 알라딘에서 쪽수·표지·분야를 보충합니다. 못 찾은 책은 목록으로 따로 보여 줍니다. 4. 7개 연도의 책장이 한꺼번에 생깁니다.

              시나리오 C: 연말 회고 (12월) 1. 2026년 책장에서 "그해의 책"을 1권 고르고, 한 줄 회고를 씁니다. 2. 연도 비교 화면에서 2025년과 겹쳐 보며 "올해는 인문 비중이 늘었다"를 확인합니다. 3. 회고 카드(올해 책장 + 권수·쪽수 + 그해의 책 + 한 줄 회고)를 PNG로 저장해 SNS에 올립니다.

              3. 전체 사용 흐름

              [첫 실행] ─ 환영 화면 ─┬─ 책 검색으로 시작
                        └─ CSV 가져오기로 시작
                                │
                                ▼
                     [책장 홈: 연도별 책장 목록]
           ┌────────────┬───────┴──────┬──────────────┐
           ▼            ▼              ▼              ▼
     [책 추가/수정]  [연도 책장 상세]  [연도 비교]   [설정·백업]
      ISBN·제목 검색   책등 탭→책 카드   지표 겹쳐 보기  CSV·JSON
           │            │
           │            ├─ 그해의 책 선정
           │            ├─ 한 줄 회고 작성
           │            └─ 회고 카드 내보내기(PNG)
           └─ 저장 → 해당 연도 책장에 책등 추가

              4. 기능 요구사항

              우선순위: P0 = 첫 버전(MVP) 필수, P1 = 첫 버전에 넣으면 좋음, P2 = 이후 버전

              F1. 책 추가·수정·삭제 (P0)

              • 입력 항목: 제목, 저자, 출판사, 출간일, ISBN-13, 쪽수, 분야, 표지 이미지, 책등 색
              • 독서 기록 항목: 상태(읽는 중·완독·중단), 시작일, 완독일, 별점(0.5 단위, 5점 만점), 한 줄 메모
              • 같은 책을 다시 읽으면 독서 기록을 하나 더 추가합니다. 책 정보는 한 번만 저장하고, 기록은 여러 개를 가질 수 있습니다.
              • 책장에 꽂히는 연도는 완독일의 연도를 기준으로 합니다. 완독일이 없으면 "연도 미상" 칸에 둡니다.
              • 수동 입력도 지원합니다(검색 결과가 없는 독립 출판물, 외서 등).

              F2. 도서 정보 자동 입력 (P0)

              • ISBN 검색: ISBN-10 또는 ISBN-13을 입력하면 알라딘 상품 조회(ItemLookUp)로 한 권을 바로 채웁니다. ISBN-10은 ISBN-13으로 변환해 저장합니다.
              • 제목·저자 검색: 알라딘 상품 검색(ItemSearch)으로 최대 20건을 보여 주고, 표지 썸네일·저자·출판사·출간 연도로 구분하게 합니다.
              • 입력 후 300ms 디바운스, 최근 검색어 5개 기억
              • 바코드 스캔(P1): 모바일에서 카메라로 ISBN 바코드를 읽습니다. 브라우저 BarcodeDetector를 쓰고, 지원하지 않는 브라우저에서는 ZXing 라이브러리로 대체합니다.
              • 자동 입력된 값은 모두 사용자가 고칠 수 있습니다.
              • 화면 하단에 "도서 DB 제공: 알라딘 인터넷서점" 출처를 표기합니다(알라딘 API 이용 조건).

              F3. CSV 가져오기 (P0)

              • UTF-8과 CP949(엑셀 기본 한글 인코딩) 파일을 모두 읽습니다. 인코딩을 자동 판별하고, 깨지면 사용자가 직접 고를 수 있게 합니다.
              • 열 매핑 화면: CSV의 열 이름을 앱 항목(제목, 저자, ISBN, 쪽수, 완독일, 별점, 메모, 분야)에 끌어 맞춥니다. 이름이 비슷하면 자동으로 맞춰 둡니다.
              • 날짜 형식 자동 인식: 2025-03-14, 2025.3.14, 2025/03/14, 20250314, 2025-03(일 없음 → 15일로 저장하고 "일 미상" 표시)
              • 보충 조회: ISBN이 있으면 ISBN으로, 없으면 "제목 + 저자"로 알라딘에서 쪽수·표지·분야를 채웁니다. 진행 막대를 보여 주고 중간에 멈출 수 있습니다.
              • 미리 보기에서 행별 상태를 표시합니다: 정상, 정보 보충됨, 후보 여러 개(직접 선택), 찾지 못함
              • 중복 판정: ISBN이 같거나, 제목·저자가 같으면 중복 후보로 표시하고 "건너뛰기 / 독서 기록만 추가 / 덮어쓰기" 중에서 고릅니다.
              • 프리셋(P1): Goodreads 내보내기 CSV 형식을 바로 인식합니다.

              F4. 연도별 책장 뷰 (P0) ※ 핵심 기능

              • 연도마다 책장 한 칸(선반)을 그리고, 그해 완독한 책을 완독일 순서로 왼쪽부터 꽂습니다. 최신 연도가 맨 위에 옵니다.
              • 책등 자동 생성 (상세 규칙은 6장)
              • 두께: 쪽수에 비례 (최소·최대 두께 제한, 화면 폭에 따라 배율 조정)
              • 높이: 판형 정보가 있으면 반영, 없으면 책마다 고정된 작은 변화를 주어 실제 책장처럼 보이게 함
              • 무늬: 표지에서 뽑은 3색 팔레트와 분야별 책등 패턴(하드커버·페이퍼백·라벨형)으로 만든 생성형 책등이 기본
              • 글자: 세로쓰기로 제목(필요하면 줄임), 아래쪽에 저자. 바탕색에 맞춰 밝은 글자·어두운 글자를 자동 선택
              • 꺼내 보기 (6.6)
              • 마우스를 올리면 책이 살짝 들려 나옵니다.
              • 누르면 책이 앞으로 빠져나오며 옆으로 돌아 실제 표지(알라딘 표지 이미지)가 보이고, 오른쪽 상세 패널에 그 책의 기록이 열립니다.
              • 선반 폭을 넘으면 다음 단으로 넘깁니다(한 연도가 여러 단이 될 수 있음).
              • 선반 위쪽에 연도와 그해 요약(권수, 총 쪽수, 그해의 책)을 표시합니다.
              • 보기 옵션
              • 정렬: 완독일순(기본) / 색상순(무지개 책장) / 분야순 / 별점순 / 쪽수순
              • 강조: 특정 분야나 별점 4.5 이상만 진하게, 나머지는 흐리게
              • 밀도: 연도 목록(여러 해를 위아래로 쌓아 보기) / 한 해 크게 보기 / 지난해 접기(지난해를 책등 색 띠로 접어 보기)
              • 그해의 책은 책등에 작은 책갈피 끈을 답니다.
              • 읽는 중인 책은 선반 끝에 비스듬히 기대어 놓은 모습으로 표시합니다(P1).

              F5. 연도 비교 (P0)

              • 비교할 연도를 2~5개 고릅니다(기본값: 올해와 작년).
              • 지표 카드: 권수, 총 쪽수, 평균 쪽수, 평균 별점, 가장 두꺼운 책, 가장 많이 읽은 분야. 작년 대비 증감을 화살표와 %로 표시
              • 월별 그래프: 월별 권수(또는 쪽수)를 연도별 선으로 겹쳐 봅니다. "누적" 토글을 켜면 1월부터의 누적 곡선으로 바뀌어 연중 페이스를 비교할 수 있습니다.
              • 분야 비중: 연도별 100% 누적 막대로 분야 구성 변화를 보여 줍니다. 분야는 상위 6개 + 기타로 묶습니다.
              • 연도별 추이(P1): 전체 연도의 권수·쪽수를 막대로 보여 주는 "독서 나이테" 요약
              • 그래프의 연도 색은 고정된 연도 팔레트를 쓰고, 색 외에 선 모양(실선·점선)이나 범례 라벨로도 구분되게 합니다(색약 배려).
              • 표로 보기 토글: 그래프와 같은 값을 표로 보여 줍니다(접근성, 정확한 값 확인용).

              F6. "그해의 책"과 한 줄 회고 (P0)

              • 연도마다 "그해의 책"을 1권 고릅니다(P1: 최대 3권까지 순위로).
              • 한 줄 회고: 연도 전체에 대한 한 줄(최대 80자). 책별 한 줄 메모와는 별도입니다.
              • 선택하지 않은 해는 별점이 가장 높은 책을 "후보"로 제안만 하고, 자동으로 정하지는 않습니다.

              F7. 연말 회고 카드 이미지 내보내기 (P0)

              • 내보내기: PNG 저장. 모바일에서는 Web Share API로 바로 공유

              5. 도서 검색 API 연동 설계

              5.1 알라딘 Open API 기본 사항

              • TTB 키: 발급 완료(보유). 키는 프록시 Worker의 비밀 값으로만 보관하고, 앱 코드·저장소·브라우저에는 두지 않습니다.
              • 사용하는 API
              API 용도 주요 파라미터
              상품 검색 ItemSearch.aspx 제목·저자 검색 Query, QueryType=Title·Author·Keyword, MaxResults=20, SearchTarget=Book, Cover=Big, Output=js, Version=20131101
              상품 조회 ItemLookUp.aspx ISBN으로 한 권 조회, 쪽수 보충 ItemId, ItemIdType=ISBN13, Cover=Big, Output=js, Version=20131101
              • 표지 크기: 공식 옵션 중 가장 큰 Cover=Big은 가로 약 200px입니다. 이미지 주소의 크기 표기를 바꿔 더 큰 이미지를 받는 방법이 알려져 있으나 공식 기능이 아니므로, 기본은 Cover=Big으로 하고 큰 이미지는 받을 수 있을 때만 쓰는 선택 사항으로 둡니다.
              • 받아 쓰는 값: title, author, publisher, pubDate, isbn13, cover, categoryName, subInfo.itemPage(쪽수, 상품 조회에서 제공)
              • 판형 크기(가로·세로·두께)는 상품 조회의 부가 정보로 제공되는지 개발 시작 시 확인하고, 있으면 책등 높이·두께에 반영합니다.
              • 하루 호출 한도와 이용 약관(비상업적 이용, 출처 표기)은 개발 시작 시 최신 기준을 다시 확인합니다.

              5.2 호출 방식: Cloudflare Workers 프록시 (확정)

              알라딘 API는 브라우저에서 바로 부르면 CORS 제한에 걸릴 수 있고, TTB 키가 웹 페이지에 그대로 드러납니다. 표지 이미지도 CORS 헤더가 없으면 캔버스에서 색을 뽑을 수 없습니다. 그래서 모든 알라딘 호출을 Cloudflare Workers 프록시를 거쳐 보냅니다.

              [PWA] ──HTTPS──▶ [서버리스 프록시: Cloudflare Workers] ──▶ [알라딘 Open API]
                    · TTB 키는 프록시 환경 변수에 보관       [알라딘 표지 이미지]
                    · 응답에 CORS 헤더 추가
                    · /search, /lookup, /cover 세 경로만 허용
                    · 결과 24시간 캐시, 앱 출처(Origin)만 허용
              • 프록시는 무료 요금제 범위에서 충분합니다(개인 사용 기준).
              • 프록시 경로 명세
              경로 알라딘 API 앱에서 보내는 값 돌려주는 값
              GET /search?q=&type= ItemSearch 검색어, 검색 종류(title·author·keyword) 필요한 필드만 추린 책 목록(JSON)
              GET /lookup?isbn= ItemLookUp ISBN-13 책 한 권(쪽수 포함, JSON)
              GET /cover?url= 표지 이미지 알라딘 표지 주소(알라딘 이미지 도메인만 허용) 이미지 원본 + CORS 헤더
              • Worker는 알라딘 응답을 앱 형식(7.2의 books 필드 이름)으로 바꿔 돌려주어, 앱 코드가 알라딘 응답 구조에 묶이지 않게 합니다.

              5.3 분야 매핑

              알라딘 categoryName은 국내도서>소설/시/희곡>한국소설>2000년대 이후 한국소설처럼 계층으로 옵니다.

              • 2번째 단계(예: 소설/시/희곡, 인문학, 경제경영, 과학)를 앱의 기본 분야로 씁니다.
              • 1번째 단계가 외국도서면 2번째 단계 앞에 "외서" 표시를 붙입니다.
              • 사용자는 설정에서 분야 이름을 바꾸거나 합칠 수 있습니다(예: 에세이 + 시 → 문학).
              • 원래 categoryName 전체는 따로 저장해 두어, 나중에 매핑 규칙을 바꿔도 다시 계산할 수 있게 합니다.

              5.4 예비 API (알라딘에서 찾지 못할 때)

              • 카카오 책 검색 API: 쪽수 정보가 없으므로 제목·표지 보충용
              • 국립중앙도서관 ISBN 서지 정보 API: 독립 출판물·오래된 책 보충용
              • 첫 버전에서는 알라딘만 구현하고, 예비 API는 P2로 둡니다.

              5.5 호출 안정성

              • 요청 시간 제한 8초, 실패 시 1회 재시도
              • CSV 보충 조회는 동시에 2건씩, 요청 사이 200ms 간격을 두어 한도를 넘지 않게 합니다.
              • 같은 ISBN 조회 결과는 IndexedDB에 30일간 캐시합니다.

              5.6 프록시 구축·배포 절차

              Cloudflare 계정과 TTB 키가 이미 있으므로, 아래 순서로 M2 첫날 바로 진행합니다.

              1. 저장소 안에 proxy/ 폴더를 만들고 Worker 프로젝트를 생성합니다: npm create cloudflare@latest proxy (템플릿: Hello World Worker, TypeScript)
              2. wrangler.toml에 이름 ringshelf-proxy, 환경 변수 ALLOWED_ORIGINS(배포 주소와 http://localhost:5173)를 적습니다.
              3. TTB 키를 비밀 값으로 등록합니다: npx wrangler secret put ALADIN_TTB_KEY
              4. 로컬 개발용 키는 proxy/.dev.vars에 두고, 이 파일은 .gitignore에 넣어 저장소에 올리지 않습니다.
              5. 배포합니다: npx wrangler deploy → https://ringshelf-proxy.<계정 서브도메인>.workers.dev 주소를 받습니다.
              6. 앱의 .env에 VITE_PROXY_URL로 이 주소를 넣고 빌드합니다.

              운영 원칙

              • 보안: 허용한 출처(Origin) 외의 요청은 403으로 거절, /cover는 알라딘 이미지 도메인만 허용해 아무 이미지나 중계하는 열린 프록시가 되지 않게 합니다.
              • 캐시: Workers Cache API로 검색 결과 24시간, 표지 이미지 30일 캐시
              • 무료 요금제(하루 10만 요청 내외)는 개인 사용에 충분합니다. 한도는 배포 전에 최신 기준을 확인합니다.

              6. 책장 시각화 규칙

              화면에 그리는 방법(색, 글꼴, 치수, 애니메이션)은 ringshelf/DESIGN.md에 정리하고, 이 장은 데이터에서 책등을 만드는 규칙을 다룹니다.

              6.1 책등 두께

              두께(px) = clamp(최소 8, 최대 80, 쪽수 × 화면 배율)
화면 배율 ≈ 0.06(폭 390px) ~ 0.15(폭 1440px), 화면 폭에 비례
              • 1440px 화면에서 300쪽 → 약 45px, 600쪽 → 약 80px(최대)
              • 쪽수를 모르면 분야 평균 쪽수, 그것도 없으면 280쪽으로 가정하고 책등에 점선 테두리를 둘러 "추정값"임을 표시합니다.
              • 판형 두께(mm) 정보가 있으면 쪽수 대신 그 값을 씁니다.

              6.2 책등 높이

              • 기본 높이: 선반 높이의 80~95% 사이
              • 판형 세로 길이(mm)가 있으면 그 비율대로, 없으면 책 ID로 만든 고정 난수로 ±8% 변화를 줍니다. 고정 난수이므로 화면을 새로 고쳐도 높이가 바뀌지 않습니다.

              6.3 표지 팔레트 추출 (3색)

              1. 표지 이미지를 64×64로 줄여 캔버스에 그립니다.
              2. 흰색·검은색에 가까운 픽셀(밝기 5% 미만, 95% 초과)과 채도가 아주 낮은 테두리 픽셀을 제외합니다.
              3. 남은 픽셀을 k-평균(k=5)으로 묶고 다음 세 색을 고릅니다.
              4. 바탕색(base): "픽셀 수 × (0.5 + 채도)" 점수가 가장 높은 묶음
              5. 띠색(band): 바탕색과 밝기 차이가 가장 큰 묶음(명암비 2:1 이상 우선)
              6. 강조색(accent): 나머지 중 채도가 가장 높은 묶음. 없으면 띠색을 조금 밝게 또는 어둡게 바꿔 만듦
              7. 결과가 거의 무채색이면 무채색 그대로 씁니다(흑백 표지 책은 흑백 책등이 자연스럽습니다).
              8. 추출은 Web Worker에서 돌려 화면이 멈추지 않게 합니다.
              9. 사용자는 책 편집 화면에서 후보 5색을 보고 세 색을 각각 바꿀 수 있습니다.

              6.4 생성형 책등 패턴 (기본 책등)

              분야에 따라 세 가지 패턴 중 하나를 고르고, 6.3의 3색으로 칠합니다. 분야별 기본 패턴은 설정에서 바꿀 수 있고, 책마다 따로 지정할 수도 있습니다.

              패턴 생김새 기본 분야
              하드커버(hardcover) 바탕색 위 위·아래 끝 근처에 가는 띠 두 줄씩(강조색, 금박 느낌), 제목은 명조 계열, 아래쪽에 출판사 이니셜 사각 표시 인문, 역사, 과학, 사회, 경제경영
              페이퍼백(paperback) 위쪽 18% 정도를 띠색 블록으로 칠하고, 그 아래 바탕색에 제목, 맨 아래 강조색 가는 줄 소설/시/희곡, 장르소설
              라벨형(label) 바탕색 가운데에 밝은 띠색 라벨 상자를 두고 그 안에 제목(옛 도서관 책 라벨 느낌) 에세이, 예술, 자기계발, 기타
              • 모든 패턴 공통: 아주 옅은 종이·천 질감(노이즈)과 좌우 가장자리의 밝기 차이로 둥근 책등 느낌을 줍니다.
              • 그해의 책: 책갈피 끈(테마의 장식색)을 아래로 늘어뜨립니다.
              • 같은 데이터로 항상 같은 책등이 나오도록 무작위 요소는 모두 책 ID로 만든 고정 난수를 씁니다.

              6.5 표지 질감 모드 (설정에서 선택)

              • 책등 바탕에 표지 이미지를 크게 늘리고 흐리게(blur) 처리한 그림을 깔고, 그 위에 바탕색을 35~50% 정도 덧칠해 제목이 잘 읽히게 합니다.
              • 책마다 표지의 그림·색 분포가 그대로 무늬가 되어 생성형 책등보다 더 다채롭습니다.
              • 책을 등록할 때 Canvas로 세로 64×256px 흐림 이미지(WebP)를 한 번 만들어 spineTextures 저장소에 캐시합니다. 화면을 그릴 때마다 흐림 처리를 다시 하지 않습니다.
              • 표지가 없는 책은 생성형 책등으로 자동 대체합니다.

              6.6 꺼내 보기 상호작용

              상태 동작
              마우스 올림·키보드 포커스 책이 위로 8px 들림, 그림자 진해짐
              누름(선택) 책이 위로 들리며 앞으로 나오고 Y축으로 약 60° 돌아 표지 면이 보임. 오른쪽 상세 패널이 이 책으로 바뀜
              다른 책 누름·Esc 이전 책은 제자리로 돌아감
              움직임 줄이기 켜짐 회전 없이 들림 + 테두리 강조만
              • 표지 면에는 저장해 둔 알라딘 표지 이미지를 씁니다. 표지가 없으면 팔레트로 만든 간이 표지(제목·저자 조판)를 보여 줍니다.
              • 책은 CSS 3D(transform-style: preserve-3d)로 책등 면 + 표지 면 두 면을 가진 상자로 만듭니다.

              6.7 글자 색과 가독성

              • 글자가 놓이는 바탕(패턴에 따라 바탕색 또는 라벨색)과 밝은·어두운 글자색의 명암비를 계산해 더 높은 쪽(WCAG 대비 4.5:1 이상 목표)을 씁니다.
              • 제목은 writing-mode: vertical-rl로 세로쓰기합니다. 영문·숫자는 옆으로 눕혀 표시합니다.
              • 책등이 좁아(14px 미만) 글자가 들어가지 않으면 제목을 숨기고 상세 패널에서만 보여 줍니다.

              6.8 그리기 방식

              • 생성형 책등은 HTML 요소와 CSS로 그립니다. 테마가 바뀌어도 바로 반영되고, 클릭·포커스·스크린 리더 지원이 쉽습니다.
              • 표지 질감 모드의 흐림 그림만 미리 만든 이미지(6.5)를 씁니다.
              • 회고 카드 이미지는 같은 데이터를 Canvas에 다시 그려 PNG로 만듭니다.

              7. 데이터 모델

              7.1 IndexedDB 저장소 구성

              Dexie.js로 IndexedDB를 다룹니다. DB 이름은 ringshelf, 스키마 버전 1부터 시작합니다.

              저장소 키 인덱스 내용
              books id isbn13, title, category 책 정보(한 권당 1개)

              apiCache key savedAt 도서 검색 결과 캐시
              settings key 설정 값

              9.3 테마

              두 테마는 기능, 정보, 배치가 완전히 같고 겉모습만 다릅니다. 한쪽 테마에만 있는 기능은 만들지 않습니다.

              항목 서재 (Study, 어두움) 종이 (Paper, 밝음)
              바탕 짙은 호두나무 갈색 아이보리 종이색
              강조색 황동 남색 잉크

              책갈피 끈 황동색 남색
              • 색·글꼴·재질은 모두 디자인 토큰(CSS 변수)으로 분리하고, data-theme="study" / data-theme="paper"로 바꿉니다.
              • 기본값은 "시스템 설정 따름"으로, 운영체제가 다크 모드면 서재, 라이트 모드면 종이를 씁니다.

              10. 비기능 요구사항

              항목 기준
              성능 책 1,000권(10년치) 기준 책장 홈 첫 표시 1초 이내, 스크롤 60fps 목표. 화면 밖 연도는 지연 렌더링
              오프라인 검색을 뺀 모든 기능이 오프라인에서 동작
              저장 공간 표지는 최대 300px 폭 JPEG(품질 0.8)로 줄여 저장, 1권당 약 30KB → 1,000권 약 30MB
              접근성 책등은 키보드로 이동 가능(좌우 화살표, Enter로 꺼내 보기), 스크린 리더용 라벨("소년이 온다, 한강, 216쪽, 2026년 3월 완독"), 그래프는 표 대체 제공, prefers-reduced-motion이면 회전 애니메이션 끔
              화면 1440×900 기준 설계, 1280~2560px에서 빈 여백 없이 확장, 390px 스마트폰에서 확인용으로 동작
              개인정보 독서 기록은 기기 밖으로 보내지 않음. 프록시에는 검색어·ISBN만 전달하고 기록하지 않음
              호환성 데스크톱 최신 Chrome, Edge, Safari, Firefox(주 환경). 모바일 Safari(iOS 16.4 이상), Chrome, Samsung Internet
              국제화 v1은 한국어 UI. 문자열은 한곳에 모아 두어 영어 추가가 쉽게 함

              11. 개발 단계 (마일스톤)

              M1. 데이터와 기본 책장 (MVP, API 없음)

              • Vite + Svelte + Dexie 프로젝트 구성, 데이터 모델과 저장
              • 수동 입력으로 책 추가·수정·삭제
              • 데스크톱 3단 레이아웃(사이드바·책장·상세 패널)과 디자인 토큰 구조, 서재 테마 먼저 적용
              • 연도별 책장 뷰: 쪽수 두께, 수동 3색 팔레트, 생성형 책등 패턴 3종, 세로 제목
              • 완료 기준: 직접 입력한 30권이 3개 연도 책장에 꽂혀 보임

              M2. 도서 검색과 표지 색

              • Cloudflare Workers 프록시 구축·배포(5.6), TTB 키 비밀 값 등록, ISBN·제목 검색
              • 표지 저장과 3색 팔레트 자동 추출(Web Worker)
              • 꺼내 보기 상호작용(실제 표지로 돌아서기)
              • 분야 매핑
              • 완료 기준: 제목 검색으로 10초 안에 한 권 등록, 생성형 책등이 표지와 어울리고, 누르면 실제 표지가 보임

              M3. CSV 가져오기와 백업

              • 인코딩 판별, 열 매핑, 보충 조회, 중복 처리
              • JSON 백업·복원, CSV 내보내기
              • 완료 기준: 200행 CSV를 가져와 5분 안에 정리 완료

              M4. 연도 비교와 회고

              • 지표 카드, 월별(누적) 그래프, 분야 비중 막대
              • 그해의 책, 한 줄 회고, 회고 카드 PNG 내보내기·공유
              • 완료 기준: 연말 회고 카드를 만들어 휴대폰 사진첩에 저장

              M5. PWA와 다듬기

              • 서비스 워커, 설치 안내, 오프라인 동작
              • 종이 테마 추가와 테마 전환(시스템 설정 따름), 표지 질감 모드, 움직임 줄이기
              • 900px 미만 반응형(상단 바, 접히는 메뉴), 900~1199px 상세 서랍
              • 정렬·강조 옵션, 지난해 접기(책등 색 띠)
              • P1 기능(바코드 스캔, Goodreads 프리셋, 읽는 중 표시)
              • 완료 기준: 비행기 모드에서 책장·비교·회고 카드 모두 동작

              12. 위험 요소와 대응

              위험 영향 대응
              알라딘 API의 CORS 제한, TTB 키 노출 브라우저에서 검색 불가 Cloudflare Workers 프록시(5.2, 5.6), 키는 Worker 비밀 값으로만 보관
              표지 이미지 CORS로 캔버스 색 추출 실패 책등 색 자동 생성 불가 프록시 /cover 경로로 이미지를 받아 Blob으로 저장 후 추출. 실패 시 분야별 기본색
              쪽수 정보 누락 책등 두께 부정확 분야 평균으로 추정하고 점선 표시, 사용자가 수정
              CSV 형식이 제각각 가져오기 실패 열 매핑 화면, 날짜 형식 여러 개 지원, 행별 오류 표시
              브라우저 데이터 삭제로 기록 손실 치명적 영구 저장 요청, 30일 백업 알림, 쉬운 JSON 백업
              iOS Safari의 저장소 정리 정책 오래 안 쓰면 데이터 삭제 가능 홈 화면 설치 권장(설치형 PWA는 정리 대상에서 제외됨), 백업 알림
              API 이용 한도·약관 변경 검색 중단 결과 캐시, 예비 API(P2), 수동 입력은 항상 가능
              TTB 키가 실수로 저장소에 올라감 키 도용·호출 한도 소진 .dev.vars·.env gitignore, 유출 시 알라딘에서 키 재발급 후 wrangler secret put으로 교체
              알라딘 표지 해상도가 낮음(가로 약 200px) 꺼내 보기 표지가 흐릿함 표지 면 크기를 이미지 해상도에 맞춰 제한, 큰 이미지는 받을 수 있을 때만 사용
              표지 질감 모드에서 제목이 안 읽힘 가독성 저하 바탕색 덧칠(35~50%)과 명암비 계산, 필요하면 제목 뒤에 라벨 상자 자동 추가
              두 테마 유지 비용 화면마다 두 번 점검 배치는 하나로 통일하고 토큰만 분리, 화면 점검 체크리스트에 두 테마 모두 포함
              책이 많은 해의 화면 성능 스크롤 끊김 화면 밖 연도 지연 렌더링, 책등 요소 단순화

              13. 성공 지표 (개인 사용 기준)

              • 책 한 권 등록에 걸리는 시간: 평균 10초 이내
              • 과거 기록 가져오기: 200권을 10분 안에 모두 책장에 꽂기
              • 자동 생성 책등(팔레트·패턴)을 그대로 쓰는 비율: 80% 이상(직접 바꾸는 비율 20% 이하)
              • 1년 동안 매달 1회 이상 앱 사용, 연말 회고 카드 1회 이상 내보내기
              • 데이터 손실 0건(백업 파일로 언제든 복원 가능)

              14. 결정된 사항과 남은 확인 사항

              14.1 결정된 사항 (v0.3)

              • 앱 이름: 나이테 책장 (Ringshelf)
              • 도서 검색: 알라딘 Open API (TTB 키 보유)
              • 호출 방식: Cloudflare Workers 프록시 (계정 보유), TTB 키는 Worker 비밀 값으로만 보관
              • 주 사용 환경: 데스크톱 웹 브라우저(16:10), 스마트폰은 반응형 확인용
              • 디자인: 통일 레이아웃 1개(사이드바·책장·상세 패널) + 테마 2종(서재·종이)
              • 책등: 생성형 책등이 기본, 꺼내 보기로 실제 표지 표시, 표지 질감 모드는 설정에서 선택

              14.2 아직 결정할 사항

              • UI 프레임워크: Svelte 5와 순수 TypeScript 중 선택
              • 앱 배포 위치: GitHub Pages와 Cloudflare Pages 중 선택 (Cloudflare 계정이 있으므로 Cloudflare Pages를 쓰면 프록시와 한곳에서 관리할 수 있어 편리합니다)
              • "한 해의 기준" 기본값: 완독일 기준(제안) 유지 여부
              • 회고 카드에 넣을 기본 항목
              • 분야별 기본 책등 패턴(6.4 표의 제안) 유지 여부

              14.3 개발 시작 시 확인할 사항

              • 알라딘 API 하루 호출 한도, 이용 약관(출처 표기 방식) 최신 기준
              • 상품 조회 API에서 쪽수(itemPage)와 판형 크기 정보가 실제로 오는지
              • 알라딘 표지 이미지 도메인 목록(/cover 허용 목록에 넣을 주소)
              • Cloudflare Workers 무료 요금제 한도 최신 기준
              • iOS Safari에서 Web Share API로 PNG 파일 공유가 되는지
              • Cover=Big 표지의 실제 해상도와, 더 큰 표지 주소를 써도 되는지(약관)
