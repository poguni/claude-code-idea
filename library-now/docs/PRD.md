## 1. 개요

### 1.1 배경
동네 도서관에 가려고 할 때 자주 생기는 문제는 다음과 같습니다.

1. **헛걸음**: 휴관일이 도서관마다 다릅니다. "매주 월요일", "매월 둘째·넷째 월요일", "법정공휴일"처럼 규칙이 제각각이고, 공휴일이 끼면 더 헷갈립니다.
2. **자료실과 열람실의 시간 차이**: 책을 빌리는 자료실은 18시에 닫아도 공부하는 열람실은 22시까지 여는 경우가 많습니다. 어떤 목적으로 가는지에 따라 답이 달라집니다.
3. **정보가 흩어져 있음**: 구립, 시립, 교육청 소속 도서관마다 홈페이지가 달라서 한눈에 비교하기 어렵습니다.
4. **구 경계**: 구로구·영등포구·양천구의 경계 근처에 살면 다른 구의 도서관이 더 가까울 수 있습니다.

### 1.2 목표
- 앱을 열고 **3초 안에** "지금 갈 수 있는 도서관"을 알 수 있게 합니다.
- 도서관마다 **"지금 가면 ○시간 ○분 이용 가능"**을 도착 시각 기준으로 계산해 보여 줍니다.
- 자료실(책 빌리기)과 열람실(공부하기)을 구분해서 판단합니다.
- 내 위치나 저장한 출발지(집, 직장)에서 찾아가는 방법을 바로 열 수 있게 합니다.
- 비용 0원으로 운영합니다(유료 API, 서버, DB 없음).
- 포트폴리오에 올릴 수 있는 완성도의 반응형 웹앱을 만듭니다.

### 1.3 범위에서 제외하는 것 (Non-goals)
- 로그인, 회원가입, 서버 백엔드, DB, 기기 간 동기화
- 작은도서관, 대학도서관, 전문도서관 (1차 범위는 공공도서관만)
- 앱 안에서 대중교통 경로를 직접 계산하는 기능 (카카오맵·네이버 지도로 넘김)
- 열람실 실시간 좌석 현황, 도서 예약·대출 처리
- 앱스토어용 네이티브 앱
- 지도 타일 오프라인 저장 (OSM 타일 정책상 금지)

## 2. 사용자와 사용 시나리오

### 2.1 주 사용자
- **본인(개발자 겸 유일한 사용자)**: 서울 구로구 인근에 살며, 책을 빌리러 가거나 공부하러 도서관을 이용합니다. 데스크탑과 스마트폰을 모두 씁니다.
- **포트폴리오 방문자(간접 사용자)**: 포트폴리오 사이트에서 링크를 눌러 앱을 체험해 봅니다. 위치 권한 없이도 기본 화면이 의미 있게 보여야 합니다.

### 2.2 대표 시나리오

> **시나리오 A. 퇴근 후 공부하러 갈 곳 찾기 (스마트폰)**
> 평일 저녁 7시, 회사에서 나오며 앱을 엽니다. 상단 모드를 **공부하기**로 바꾸고 출발지를 **직장**으로 고릅니다. 목록 맨 위에 "열람실 22시까지 · 지금 가면 2시간 25분 이용 가능 · 약 35분 거리" 카드가 보입니다. **카카오맵으로 길찾기**를 눌러 대중교통 경로를 확인하고 출발합니다.

> **시나리오 B. 월요일에 책 반납하러 가기 (데스크탑)**
> 월요일 오전, 집에서 노트북으로 앱을 엽니다. 모드는 **책 빌리기**입니다. 구로구 도서관 대부분이 "오늘 휴관"으로 회색 처리되어 있고, 양천구의 한 도서관이 "자료실 운영 중 · 18시까지"로 표시됩니다. 지도에서 그 도서관을 눌러 오른쪽 패널에서 주소와 운영시간 원문을 확인합니다.

> **시나리오 C. 다음 주 일정 계획하기 (데스크탑)**
> 오른쪽 패널의 **달력**에서 즐겨찾기한 도서관 3곳의 이번 달 휴관일을 한 번에 봅니다. 다음 주 수요일이 공휴일이라 두 곳이 쉬는 것을 확인하고, 그날은 문 여는 나머지 한 곳에 가기로 합니다.

## 3. 전체 사용 흐름

```
앱 열기
 ├─ (처음) 위치 권한 요청 → 거부해도 기본 지역(구로구) 중심으로 표시
 ├─ 상단: 모드 [책 빌리기 | 공부하기] · 출발지 [현재 위치 | 집 | 직장] · 기준 시각 [지금 | 직접 선택]
 ├─ 지도 + 목록: 상태 배지(열림 / 곧 닫힘 / 곧 열림 / 오늘 휴관 / 운영 종료)
 │    └─ 필터: 구 선택, 지금 열린 곳만, 21시 이후 운영, 주말 운영, 즐겨찾기만
 ├─ 도서관 선택 → 상세 패널
 │    ├─ 자료실·열람실 운영시간, 휴관 규칙, 이번 달 달력
 │    ├─ "지금 가면 ○시간 ○분 이용 가능" (이동 시간 추정 포함)
 │    └─ 길찾기 버튼: 카카오맵 / 네이버 지도, 주소 복사, 홈페이지
 └─ 달력 탭: 즐겨찾기 도서관들의 월간 휴관일 겹쳐 보기
```

## 4. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = MVP 직후, **P2** = 확장

### F1. 도서관 지도 (P0)
- Leaflet과 OpenStreetMap 타일로 지도를 표시합니다.
- 도서관마다 마커를 표시하며, 마커의 색과 아이콘으로 상태를 구분합니다(색만으로 구분하지 않도록 아이콘 모양도 다르게 합니다).
- 마커를 누르면 간단한 팝업(이름, 상태, 남은 시간)이 뜨고, 상세 패널이 열립니다.
- 목록에서 도서관에 마우스를 올리거나 선택하면 지도의 해당 마커가 강조됩니다.
- 내 위치와 저장한 출발지를 별도 마커로 표시합니다.
- "내 위치로 이동", "전체 보기" 버튼을 둡니다.
- 지도 화면 오른쪽 아래에 OSM 출처(© OpenStreetMap contributors)를 표시합니다.

### F2. 지역 선택 (P0)
- 1차 지원 지역은 **구로구, 영등포구, 양천구**입니다.
- 구 선택은 여러 개를 동시에 고를 수 있는 칩 형태로 합니다. 기본값은 세 구 모두 선택입니다.
- "내 주변" 보기: 출발지에서 반경(1km, 3km, 5km) 안의 도서관을 구와 관계없이 보여 줍니다.
- 지역 목록은 데이터에서 읽어 오므로, 서울 전체로 확대할 때 코드 수정 없이 데이터만 추가하면 됩니다.

### F3. 이용 모드: 책 빌리기 / 공부하기 (P0)
- 상단에 모드 스위치를 둡니다.
  - **책 빌리기**: 자료실 운영시간을 기준으로 판단합니다.
  - **공부하기**: 열람실 운영시간을 기준으로 판단합니다.
- 상태 배지, "지금 열린 곳만" 필터, 남은 이용 시간 계산이 모두 선택한 모드를 따릅니다.
- 열람실이 없는 도서관은 공부하기 모드에서 "열람실 없음"으로 표시하고, "지금 열린 곳만" 필터에서는 제외합니다.
- 마지막으로 선택한 모드를 브라우저에 저장합니다.

### F4. 운영 상태 배지 (P0)
선택한 모드와 기준 시각(기본: 지금)에 따라 아래 상태 중 하나를 표시합니다.

| 상태 | 조건 | 표시 예 |
|---|---|---|
| 열림 | 운영 중이고 마감까지 60분 넘게 남음 | 🟢 운영 중 · 22:00까지 |
| 곧 닫힘 | 운영 중이고 마감까지 60분 이하 | 🟠 곧 닫힘 · 40분 남음 |
| 곧 열림 | 오늘 운영일이고 아직 개관 전 | 🔵 09:00 개관 |
| 운영 종료 | 오늘 운영일이었지만 마감 시각이 지남 | ⚪ 오늘 운영 종료 · 내일 09:00 |
| 오늘 휴관 | 정기 휴관일, 공휴일 휴관, 임시 휴관 | ⚫ 오늘 휴관 (매주 월요일) |
| 정보 없음 | 해당 실의 운영시간 데이터가 없음 | ❔ 운영시간 확인 필요 |

- 휴관 사유(정기 휴관, 공휴일, 임시 휴관)를 함께 보여 줍니다.
- "운영 종료"와 "오늘 휴관"일 때는 **다음 개관 시각**을 계산해 보여 줍니다.

### F5. "지금 가면 몇 시간 이용 가능" (P0, 창의 포인트)
- 도서관마다 **도착 예정 시각 기준 이용 가능 시간**을 계산합니다.
  - 이용 가능 시간 = 마감 시각 − max(도착 예정 시각, 개관 시각)
  - 도착 예정 시각 = 기준 시각 + 예상 이동 시간 (F7)
- 도착하면 이미 마감인 경우 "도착 시 마감"으로 표시하고 목록 뒤쪽으로 보냅니다.
- 이용 가능 시간이 30분 미만이면 경고 색으로 표시합니다.
- 출발지가 없으면(위치 거부, 출발지 미설정) 이동 시간을 빼지 않고 "지금부터 마감까지 ○시간"으로 표시합니다.

### F6. 출발지 관리: 현재 위치, 집, 직장 (P0)
- 출발지는 **현재 위치 / 집 / 직장** 중에서 고릅니다.
- 집과 직장은 설정 화면에서 **지도를 눌러 위치를 찍거나**, 도서관 마커처럼 핀을 끌어서 지정합니다. 이름(예: "집", "회사")도 바꿀 수 있습니다.
- 저장 위치는 브라우저(localStorage)입니다. 서버로 보내지 않습니다.
- 현재 위치는 브라우저 위치 기능(Geolocation API)을 씁니다. 거부하거나 실패하면 집 → 직장 → 기본 지역 중심 순서로 대신 씁니다.
- 데스크탑은 현재 위치가 부정확한 경우가 많으므로, 정확도가 낮으면(오차 500m 초과) "집/직장 출발지 사용을 권장"하는 안내를 보여 줍니다.
- (P1) 주소 검색으로 출발지를 지정하는 기능은 무료 지오코딩 방법을 확인한 뒤 추가합니다.

### F7. 거리와 이동 시간 추정 (P0)
- 출발지와 도서관 사이의 **직선거리**를 계산합니다(하버사인 공식).
- 실제 길은 직선보다 길므로 **우회 계수 1.3**을 곱한 값을 예상 이동 거리로 씁니다.
- 예상 이동 시간은 다음 규칙으로 추정합니다(정확한 경로 안내는 F8의 외부 지도 앱이 담당).

| 예상 이동 거리 | 수단 가정 | 계산 |
|---|---|---|
| 1.5km 이하 | 도보 | 거리 ÷ 4.2km/h |
| 1.5km 초과 | 대중교통 | 10분(정류장 도보·대기) + 거리 ÷ 18km/h |

- 화면에는 "약 25분 (추정)"처럼 추정값임을 밝힙니다.
- 계산 상수(우회 계수, 속도, 기준 거리)는 설정 파일 한 곳에 모아 두고 나중에 조정할 수 있게 합니다.
- 목록 정렬: **거리순(기본) / 남은 이용 시간순 / 이름순**.

### F8. 길찾기 연결 (P0)
- 상세 패널에 길찾기 버튼을 둡니다. 출발지 좌표가 있으면 출발지를 함께 넘깁니다.

| 버튼 | 연결 방식 | 비고 |
|---|---|---|
| 카카오맵으로 길찾기 | 웹 링크 `https://map.kakao.com/link/to/{이름},{위도},{경도}` (출발지 포함 시 `link/from/{출발지명},{위도},{경도}/to/...`) | 데스크탑과 스마트폰 모두 동작. 스마트폰에 앱이 있으면 앱으로 열림 |
| 네이버 지도로 길찾기 | 앱 스킴 `nmap://route/public?slat=&slng=&sname=&dlat=&dlng=&dname=&appname={앱 주소}` | 스마트폰에서만 표시. 앱이 없으면 네이버 지도 웹으로 대신 연결 |
| 주소 복사 | 클립보드 복사 | 다른 지도 앱을 쓸 때 |
| 홈페이지 | 도서관 홈페이지 새 탭 | 임시 휴관 공지 확인용 |

- 링크 형식은 개발 단계에서 실제 기기(PC, Android, iPhone)로 동작을 확인한 뒤 확정합니다. 특히 대중교통 탭이 바로 열리는지 확인합니다.

### F9. 목록과 필터 (P0)
- 도서관 카드: 이름, 구, 상태 배지, 남은 이용 시간, 예상 이동 시간, 오늘 운영시간(자료실·열람실), 즐겨찾기 버튼.
- 필터:
  - 지금 열린 곳만 (P0)
  - 21시 이후까지 운영 (P0, 공부하기 모드에서 유용)
  - 주말 운영 (P1)
  - 즐겨찾기만 (P0)
- 이름 검색 (P0).
- 결과가 없으면 "조건에 맞는 도서관이 없습니다. 다음 개관이 가장 빠른 곳: ○○도서관 (내일 09:00)"처럼 대안을 제안합니다.

### F10. 도서관 상세 (P0)
- 기본 정보: 이름, 구, 주소, 전화번호(누르면 전화 걸기), 홈페이지, 소속(구립/시립/교육청).
- 운영시간 표: 자료실과 열람실을 나란히, 평일·토요일·일요일·공휴일별로 표시합니다. 하절기·동절기 구분이 있으면 함께 표시합니다.
- 휴관 규칙: 사람이 읽을 수 있는 문장으로 표시합니다(예: "매주 월요일, 법정공휴일(일요일 제외)").
- 자료실 안의 세부 실(어린이자료실, 디지털자료실 등) 시간이 다르면 **메모**로 보여 줍니다.
- 이번 달 미니 달력: 휴관일을 표시합니다.
- 데이터 출처, **데이터 기준일**, **마지막 확인일**을 표시합니다.
- "방문 전 홈페이지 공지에서 임시 휴관 여부를 확인하세요" 안내를 둡니다.

### F11. 휴관일 달력 (P0)
- 월간 달력에서 날짜마다 휴관하는 도서관을 표시합니다.
- 기본은 **즐겨찾기 도서관**만 겹쳐 보여 줍니다(도서관마다 고유 색 점). 즐겨찾기가 없으면 선택한 구 전체의 "문 연 도서관 수"를 날짜마다 보여 줍니다.
- 날짜를 누르면 그날 문 여는 도서관과 운영시간 목록을 보여 줍니다.
- 공휴일과 임시공휴일은 날짜에 이름과 함께 표시합니다.

### F12. 즐겨찾기 (P0)
- 도서관 카드와 상세에서 별 버튼으로 추가·삭제합니다.
- 브라우저(localStorage)에 저장합니다.

### F13. 기준 시각 바꾸기 (P1)
- 기본은 "지금"입니다. 날짜와 시각을 직접 고르면 그 시점 기준으로 상태와 남은 시간을 다시 계산합니다.
- 예: "토요일 오후 3시에 출발하면 어디가 열려 있지?"

### F14. 내 메모와 임시 휴관 직접 추가 (P1)
- 도서관마다 개인 메모를 남깁니다(예: "3층 창가 자리 좋음").
- 공사·행사로 인한 임시 휴관 기간을 직접 입력하면 상태 계산에 반영합니다.
- 브라우저에 저장하며, JSON 파일로 내보내기·가져오기를 지원합니다(기기를 바꿀 때 사용).

### F15. 홈 화면 설치(PWA) (P1)
- 웹 앱 매니페스트와 서비스 워커를 추가해 스마트폰 홈 화면에 설치할 수 있게 합니다.
- 앱 화면과 도서관 JSON 데이터는 캐시해서 오프라인에서도 목록·운영시간·달력을 볼 수 있게 합니다. 지도 타일은 캐시하지 않습니다(OSM 정책).

### F16. 화면 테마 (P0)
- 세 가지 테마를 제공하고, 설정 화면에서 바꿀 수 있게 합니다.

| 테마 | 분위기 | 비고 |
|---|---|---|
| **서재 (Stacks)** | 도서관 느낌: 종이 바탕, 짙은 녹색, 놋쇠색, 명조 제목 | **기본 테마** |
| 말랑 (Soft) | 파스텔, 둥글고 귀여운 느낌 | |
| 모노 (Mono) | 모던하고 세련된 느낌: 검정·회색, 코발트 블루 | |

- 세 테마는 **같은 화면 구조와 기능**을 쓰고, 색·글꼴·모서리·장식만 다릅니다. 테마를 바꿔도 배치와 기능이 달라지지 않아야 합니다.
- 구현은 최상위 요소의 `data-theme` 속성과 CSS 변수(디자인 토큰)로 합니다. 상세 규칙은 `design/DESIGN.md`를 따릅니다.
- 선택한 테마는 브라우저에 저장하고, 다음 접속 때 그대로 적용합니다. 저장값이 없으면 서재 테마를 씁니다.
- 첫 화면이 그려지기 전에 테마를 적용해 테마가 깜박이며 바뀌지 않게 합니다(`index.html`의 작은 인라인 스크립트로 `data-theme` 먼저 설정).
- 테마별 글꼴은 사용 중인 테마의 것만 불러옵니다.
- 지도 타일에는 테마 분위기에 맞는 CSS 필터를 적용합니다(마커·팝업에는 적용하지 않음).
- 다크 모드는 이번 범위에 넣지 않습니다(F17).

### F17. 확장 기능 (P2)
- 서울 25개 구 전체로 확대
- 카카오맵 지도 적용(설정에서 지도 종류 선택)
- 도서관 정보나루 API로 "이 책이 있고 지금 문 연 도서관" 찾기
- 구 경계선 표시
- 다크 모드
- 링크 공유(URL에 선택한 도서관과 모드를 담기)

## 5. 시간 계산 로직

### 5.1 기준 시간대
- 모든 계산은 **한국 표준시(Asia/Seoul)** 기준으로 합니다. 기기의 시간대가 달라도 결과가 같도록 `Intl.DateTimeFormat`으로 서울 시각을 구해 사용합니다.

### 5.2 하루 운영 판정 순서
특정 날짜, 특정 실(자료실 또는 열람실)에 대해 다음 순서로 판정합니다.

1. **임시 휴관**(데이터의 `closures` 또는 사용자가 입력한 임시 휴관)에 해당하면 → 휴관
2. **정기 휴관 규칙**(매주 ○요일, 매월 ○째 ○요일)에 해당하면 → 휴관
3. **공휴일**이면 → 공휴일 규칙에 따라 휴관 또는 공휴일 운영시간 적용
4. 요일에 맞는 운영시간(평일/토요일/일요일) 적용, 하절기·동절기 구분이 있으면 날짜에 맞는 계절 적용
5. 해당 요일의 운영시간이 없으면 → 휴관(그날 운영하지 않음)

### 5.3 휴관 규칙의 표현
휴관일 문장을 다음과 같은 규칙으로 바꿔 저장합니다.

| 원문 예 | 규칙 |
|---|---|
| 매주 월요일 | `weekly: [1]` |
| 매월 둘째·넷째 월요일 | `monthly: [{ nth: [2, 4], weekday: 1 }]` |
| 매월 마지막 화요일 | `monthly: [{ nth: [-1], weekday: 2 }]` |
| 법정공휴일 | `holiday: "closed"` |
| 법정공휴일 (일요일 제외) | `holiday: "closed_except_sunday"` |
| 설·추석 연휴만 휴관 | `holiday: "seollal_chuseok_only"` |
| 공휴일 정상 운영 | `holiday: "open"` (공휴일 운영시간 사용) |

- 요일 번호는 0=일요일, 1=월요일, …, 6=토요일입니다.
- 원문은 `closedRaw`에 그대로 보관해 화면에 함께 보여 주고, 변환 결과는 사람이 검수합니다.
- 규칙으로 표현하기 어려운 경우(예: "공휴일이 월요일이면 다음 날 휴관")는 `notes`에 적고, 해당 날짜를 `closures`에 직접 넣습니다.

### 5.4 공휴일 데이터
- 한국천문연구원 특일정보 API(공공데이터포털, 무료)에서 공휴일과 임시공휴일을 받아 `holidays-{연도}.json`으로 저장합니다.
- 올해와 내년 두 해분을 미리 받아 둡니다. 임시공휴일이 새로 지정되면 데이터를 다시 받아 갱신합니다.

### 5.5 남은 이용 시간 계산
```
도착 = 기준시각 + 예상이동시간
오늘 운영 구간 = [개관, 마감]  (휴관이면 없음)
if 도착 > 마감:        "도착 시 마감" → 다음 개관 시각 안내
elif 도착 < 개관:      이용 가능 = 마감 − 개관 ("09:00 개관 후 9시간")
else:                  이용 가능 = 마감 − 도착
```
- 자정을 넘겨 운영하는 경우는 1차 범위에 없지만, 마감 시각이 개관보다 작으면 다음 날로 처리하도록 구조만 열어 둡니다.

### 5.6 테스트
- 시간 계산 함수는 순수 함수로 만들고 단위 테스트를 작성합니다.
- 필수 테스트 사례: 매주 월요일 휴관, 둘째·넷째 월요일, 마지막 주, 공휴일과 정기 휴관이 겹치는 날, 일요일인 공휴일, 임시공휴일, 하절기·동절기 경계일, 마감 직전, 개관 전, 자정 직전.

## 6. 데이터 설계

### 6.1 데이터 출처

| 데이터 | 용도 | 비고 |
|---|---|---|
| 전국도서관표준데이터 (공공데이터포털) | **주 데이터**: 도서관명, 시군구, 유형, 주소, 위도·경도, 휴관일, 평일·토요일·공휴일 운영 시작/종료 시각, 홈페이지, 데이터 기준일 | 매월 초 갱신. 서울 3개 구, 유형 "공공도서관"만 추려 씁니다 |
| 서울 열린데이터광장 공공도서관 현황정보 | 교차 검증: 운영시간·휴관일·좌표 비교 | 값이 다르면 홈페이지로 최종 확인 |
| 각 도서관 홈페이지 "이용 안내" | **자료실·열람실 운영시간**, 세부 실 메모, 하절기·동절기 | 공공데이터에는 보통 운영시간이 한 줄뿐이라 직접 확인해 입력합니다 |
| 한국천문연구원 특일정보 API | 공휴일·임시공휴일 | 무료, 인증키 발급 필요 |
| OpenStreetMap 타일 | 배경 지도 | 키 없음, 출처 표기 필수 |

### 6.2 데이터 만드는 과정 (빌드 파이프라인)
```
data/raw/            공공데이터 원본 CSV (내려받은 그대로 보관)
data/overrides/      도서관별 수기 입력(자료실·열람실 시간, 휴관 규칙 검수 결과, 메모)
        ↓  scripts/build-data.ts
  1) 원본에서 서울 · 대상 구 · 공공도서관만 추리기
  2) 이름·주소 정규화, 고유 ID 부여
  3) 휴관일 문장 → 규칙 변환(자동 1차 변환)
  4) overrides 덮어쓰기(사람이 검수한 값이 항상 우선)
  5) 검증: 필수 항목, 좌표가 서울 범위 안인지, 시각 형식, 개관 < 마감
        ↓
public/data/libraries.json      앱이 읽는 도서관 데이터
public/data/holidays-2026.json  공휴일
public/data/holidays-2027.json
public/data/meta.json           데이터 기준일, 출처, 생성 시각
```
- 앱은 실행 중에 외부 API를 부르지 않고 이 JSON 파일만 읽습니다(정적 방식).
- 데이터 갱신은 월 1회 정도 수동으로 스크립트를 실행하고 변경 내용을 확인한 뒤 커밋합니다.
- 검증에 실패하면 빌드를 멈추고 문제가 있는 도서관과 항목을 출력합니다.

### 6.3 도서관 데이터 구조 (`libraries.json`의 한 항목)
```json
{
  "id": "guro-001",
  "name": "○○구립도서관",
  "district": "구로구",
  "type": "공공도서관",
  "operator": "구립",
  "address": "서울특별시 구로구 ...",
  "phone": "02-000-0000",
  "homepage": "https://...",
  "lat": 37.49,
  "lng": 126.88,
  "rooms": {
    "lending": {
      "label": "자료실",
      "hours": {
        "weekday":  { "open": "09:00", "close": "18:00" },
        "saturday": { "open": "09:00", "close": "17:00" },
        "sunday":   { "open": "09:00", "close": "17:00" },
        "holiday":  null
      },
      "seasons": null,
      "memo": "어린이자료실은 평일 17:00까지"
    },
    "reading": {
      "label": "열람실",
      "hours": {
        "weekday":  { "open": "07:00", "close": "22:00" },
        "saturday": { "open": "07:00", "close": "22:00" },
        "sunday":   { "open": "07:00", "close": "22:00" },
        "holiday":  null
      },
      "seasons": null,
      "memo": null
    }
  },
  "closed": {
    "weekly": [1],
    "monthly": [],
    "holiday": "closed",
    "appliesTo": ["lending", "reading"]
  },
  "closedRaw": "매주 월요일, 법정공휴일",
  "closures": [
    { "from": "2026-12-01", "to": "2026-12-14", "reason": "시설 보수", "rooms": ["lending", "reading"] }
  ],
  "notes": [],
  "source": {
    "dataset": "전국도서관표준데이터",
    "baseDate": "2026-11-01",
    "verifiedAt": "2026-11-20",
    "verifiedBy": "homepage"
  }
}
```
- `rooms.reading`이 `null`이면 열람실이 없는 도서관입니다.
- 열람실만 다른 날 쉬는 경우가 있으므로, 휴관 규칙에 `appliesTo`(적용 실)를 둡니다. 실마다 규칙이 다르면 `closed`를 실별 배열로 나눠 저장합니다.
- `seasons`는 하절기·동절기가 다른 도서관에서만 씁니다. 예: `[{ "from": "03-01", "to": "10-31", "hours": {...} }]`.
- `holiday` 운영시간이 `null`이고 휴관 규칙이 "open"이면 일요일 시간을 씁니다.

### 6.4 브라우저 저장 데이터 (localStorage)

| 키 | 내용 |
|---|---|
| `ln.settings` | 화면 테마(기본 `library`), 모드, 선택한 구, 정렬, 필터, 지도 종류 |
| `ln.places` | 출발지(집, 직장)의 이름과 좌표 |
| `ln.favorites` | 즐겨찾기 도서관 ID 목록 |
| `ln.notes` | (P1) 도서관별 메모, 사용자가 입력한 임시 휴관 |

- 모든 읽기·쓰기는 예외 처리합니다(사생활 보호 모드 등에서 저장이 막혀도 앱은 정상 동작).
- 저장 형식에 버전 번호를 넣어 나중에 구조가 바뀌어도 옮길 수 있게 합니다.

### 6.5 데이터 라이선스와 출처 표기
- 공공데이터와 OSM 데이터는 비상업적 개인 사용과 포트폴리오 공개 범위에서 사용합니다.

## 7. 지도와 길찾기 설계

### 7.1 지도 구성
- **1차: Leaflet + OpenStreetMap 타일** (`https://tile.openstreetmap.org/{z}/{x}/{y}.png`)
  - 키가 필요 없습니다. 출처 표기가 필수입니다.
  - 개인 사용 수준의 적은 트래픽은 정책상 문제가 없습니다. 대량 사용, 타일 일괄 다운로드, 오프라인 저장은 금지입니다.
- **지도 교체 구조**: 지도 기능을 `MapProvider` 인터페이스(마커 그리기, 이동, 확대, 클릭 이벤트) 뒤에 숨겨서, 나중에 카카오맵 구현체를 추가할 때 화면 코드를 바꾸지 않아도 되게 합니다.
  - 타일 주소도 설정 파일에서 바꿀 수 있게 해 OSM 정책이나 서비스 상황이 바뀌면 다른 타일 서비스로 쉽게 옮길 수 있게 합니다.
- **2차(P2): 카카오맵 JavaScript API**
  - 키는 빌드 환경 변수(`VITE_KAKAO_JS_KEY`)로 넣습니다. JavaScript 키는 원래 브라우저에 노출되는 키이며, 등록한 도메인에서만 동작하도록 제한합니다.
  - 설정 화면에서 지도 종류(OSM / 카카오맵)를 고를 수 있게 합니다. 키가 없으면 카카오맵 선택지를 숨깁니다.
  - 키 발급 방법은 부록 A에 정리합니다.

### 7.2 길찾기
- 앱 안에서는 직선거리 기반 **예상 이동 시간**만 계산합니다(F7).
- 실제 경로 안내는 **카카오맵·네이버 지도**로 넘깁니다(F8). 두 서비스 모두 실시간 버스·지하철 정보를 반영하므로 품질이 가장 좋고, 비용과 키가 필요 없습니다.
- 앱 안 대중교통 경로 계산(ODsay 등)은 무료 한도가 매우 작아(공식 정책 기준 Basic 하루 30회) 범위에서 제외합니다.

## 8. 화면 구성

### 8.1 공통 원칙
- 반응형으로 데스크탑과 스마트폰을 모두 지원합니다.
- **데스크탑은 화면 전체 폭을 사용**합니다. 내용을 가운데 좁은 기둥에 몰아 두고 좌우에 큰 여백을 남기는 배치는 쓰지 않습니다.
- 기준 해상도는 **1440×900 (16:10)**입니다. 이 크기에서 스크롤 없이 상단 바, 목록, 지도, 상세 패널이 한 화면에 모두 보여야 합니다.

### 8.2 데스크탑 (1200px 이상, 기준 1440×900)
```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 지금 열린 도서관  [구로][영등포][양천] [책 빌리기|공부하기] 출발:[집▾] 기준:[지금▾] ⚙ │ 56px
├──────────────┬────────────────────────────────────────────┬──────────────────┤
│ 검색·필터     │                                            │ 상세 / 달력 탭     │
│ 정렬 [거리▾]  │                                            │                  │
│──────────────│                 지도 (가변 폭)               │ ○○도서관          │
│ 🟢 ○○도서관   │                                            │ 🟢 열람실 22:00까지│
│  2시간 25분   │        ● 마커  ● 마커                        │ 지금 가면 2h 25m   │
│  약 20분 거리 │                    ◎ 출발지                 │ [카카오맵][주소복사]│
│ 🟠 △△도서관   │           ● 마커                            │ 운영시간 표        │
│ ⚫ □□도서관   │                                            │ 이번 달 달력        │
│   …          │                                [내 위치][전체]│                  │
├──────────────┴────────────────────────────────────────────┴──────────────────┤
  왼쪽 360px                  가운데 나머지 전부(약 680px)              오른쪽 400px
```
- 왼쪽 패널(목록)은 360px, 오른쪽 패널(상세·달력)은 400px입니다. 가운데 지도가 나머지 폭을 모두 씁니다.
- 오른쪽 패널은 접을 수 있습니다. 접으면 지도가 약 1,080px로 넓어집니다.
- 화면이 1440px보다 넓으면 지도가 더 넓어지고, 양쪽 패널은 최대 폭(목록 420px, 상세 480px)까지만 늘어납니다.
- 오른쪽 패널은 도서관을 고르지 않았을 때 "오늘 요약"(문 연 곳 수, 가장 늦게까지 여는 곳, 즐겨찾기 상태)을 보여 줍니다.
- 키보드 단축키(P1): `/` 검색, `M` 모드 전환, `↑↓` 목록 이동.

### 8.3 태블릿 (768~1199px)
- 왼쪽 목록(320px) + 지도로 2단 구성합니다.
- 상세는 지도 위에 오른쪽에서 열리는 서랍(드로어)으로 표시합니다.

### 8.4 스마트폰 (767px 이하, 기준 390×844)
- 지도를 화면 전체에 깔고, 목록은 아래에서 끌어 올리는 **바텀 시트**로 보여 줍니다(3단계: 살짝 보기 / 절반 / 전체).
- 상단에는 모드 스위치와 출발지 선택만 남기고, 구 선택과 필터는 시트 안으로 옮깁니다.
- 도서관을 누르면 시트가 상세 화면으로 바뀝니다. 길찾기 버튼은 화면 아래에 크게 고정합니다.
- 아래 탭: **지도 / 목록 / 달력 / 설정**.
- 터치 영역은 최소 44×44px로 합니다.

### 8.5 설정 화면
- 출발지 관리(집, 직장: 지도에서 위치 지정, 이름 변경, 삭제)
- 화면 테마(서재 / 말랑 / 모노, 각 테마의 작은 미리보기와 함께 선택)
- 기본 지역, 기본 모드
- 지도 종류(OSM / 카카오맵, P2)
- 데이터 정보(기준일, 출처, 라이선스)
- 내 데이터 내보내기·가져오기(P1), 초기화

### 8.6 디자인 방향
- 세부 디자인은 **`design/DESIGN.md`**(디자인 가이드)와 **`design/design-library.html`, `design-pastel.html`, `design-mono.html`**(시안)을 따릅니다. 이 문서와 디자인 문서가 다르면 디자인 문서를 우선합니다.
- 상태는 색 + 기호 + 글자로 표시합니다: 운영 중 ●, 곧 닫힘 ◔, 곧 열림 ○, 운영 종료 ◐, 휴관 ✕.
- 숫자 정보(남은 시간, 거리)는 크게, 보조 정보는 작게 해 목록을 빠르게 훑을 수 있게 합니다.
- 테마 3종(서재·말랑·모노)은 F16을 따릅니다. 기본은 서재입니다.

### 9.1 기술 스택

| 구분 | 선택 | 이유 |
|---|---|---|

| 아이콘 | Lucide (lucide-react) | 시안과 같은 선 아이콘 스타일, 무료 |

| 테스트 | Vitest(시간 계산·데이터 검증), Playwright(1440×900·390×844 화면 확인) | |
| PWA | vite-plugin-pwa | P1 |
| 배포 | GitHub Actions → GitHub Pages | 무료, main 브랜치에 반영되면 자동 배포 |

## 11. 개발 단계 (마일스톤)

### M0. 준비와 데이터 수집
- GitHub 저장소 `library-now` 생성(Public)
- `CLAUDE.md`, `docs/`(PRD), `design/`(디자인 가이드·시안)을 저장소에 먼저 넣고 첫 커밋
- Vite + React + TS 초기 설정, GitHub Pages 배포 확인
- 테마 토큰(`src/styles/themes.css`)을 시안에서 옮기고 서재 테마를 기본으로 적용
- 전국도서관표준데이터에서 구로구·영등포구·양천구 공공도서관 추리기
- 도서관 홈페이지에서 자료실·열람실 운영시간, 휴관 규칙 확인 후 `overrides`에 입력·검수
- 공휴일 JSON 생성
- 완료 기준: `libraries.json` 검증 통과, 전 도서관 `verifiedAt` 기록

### M1. 지도와 상태 표시 (MVP 핵심)
- Leaflet 지도에 3개 구 공공도서관 마커 표시
- 시간 계산 엔진(휴관 판정, 상태, 다음 개관) + 단위 테스트
- 책 빌리기 / 공부하기 모드, 상태 배지, 휴관 요일 표기
- 목록·지도 연동, 데스크탑 3단 배치 기본형
- 완료 기준: 원래 아이디어의 첫 MVP("도서관 목록을 지도에 표시하고 휴관 요일 표기")를 3개 구로 달성

### M2. 출발지, 남은 이용 시간, 길찾기
- 현재 위치, 집·직장 출발지 저장(지도에서 지정)
- 거리·이동 시간 추정, "지금 가면 ○시간 ○분 이용 가능"
- 정렬(거리, 남은 시간), 필터(지금 열린 곳, 21시 이후)
- 카카오맵·네이버 지도 길찾기 연결, 실제 기기 확인

### M3. 상세, 달력, 반응형 마감
- 상세 패널(운영시간 표, 휴관 규칙, 미니 달력, 출처·기준일)
- 휴관일 달력(즐겨찾기 겹쳐 보기), 즐겨찾기
- 태블릿 드로어, 스마트폰 바텀 시트
- 테마 3종 완성(말랑·모노 장식 적용), 설정 화면의 테마 선택, 지도 타일 필터
- Playwright로 1440×900, 390×844 화면을 테마 3종 모두 확인

### M4. 다듬기와 배포 (P1)
- 기준 시각 바꾸기, 내 메모·임시 휴관 입력, 내보내기·가져오기
- PWA(홈 화면 설치, 데이터 오프라인 보기)
- README(스크린샷, 기능 소개, 데이터 출처), 포트폴리오 등록용 소개 문구

### M5. 확장 (P2)
- 서울 25개 구로 확대(데이터 수집 → 검수 → 추가)
- 카카오맵 지도 적용
- 도서관 정보나루 연동 "이 책이 있는 문 연 도서관"(정적 방식으로는 어려우므로 별도 검토)

## 12. 위험 요소와 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 공공데이터의 운영시간이 오래되었거나 틀림 | 헛걸음 | 홈페이지로 직접 검수, 마지막 확인일 표시, 월 1회 갱신 |
| 자료실·열람실 시간이 공공데이터에 없음 | 핵심 기능 불가 | 홈페이지에서 수기 수집(`overrides`). 3개 구 약 30~40곳으로 예상되어 감당 가능 |
| 휴관 규칙 문장 해석 오류 | 상태 오판 | 자동 변환 후 사람이 검수, 원문을 화면에 함께 표시, 단위 테스트 |
| 임시 휴관·시험기간 연장 운영 | 데이터에 없음 | 홈페이지 공지 확인 안내, 사용자 직접 입력(F14) |
| 이동 시간 추정이 실제와 다름 | 남은 시간 오차 | "추정" 표기, 정확한 시간은 외부 지도 앱에서 확인하도록 안내, 계수 조정 가능 |
| 데스크탑 위치 정확도 낮음 | 거리 오차 | 집·직장 출발지 사용 안내 |
| 길찾기 링크 형식 변경·기기별 차이 | 버튼 동작 안 함 | 실제 기기로 확인, 링크 생성 코드를 한 곳에 모아 쉽게 수정, 주소 복사 대안 제공 |
| OSM 타일 정책·가용성 | 지도 안 보임 | 개인 사용 수준 유지, 타일 주소 설정 분리, 카카오맵 전환 경로 확보 |
| 공공데이터 사이트 접속 제한(개발 환경) | 데이터 수집 지연 | 원본 CSV를 직접 내려받아 `data/raw/`에 넣거나, 개발 환경에서 해당 사이트 접속 허용 |

### 14.2 개발 시작 시 확인할 사항
1. GitHub에 `library-now` 저장소를 만들어 주시면 개발 세션에 연결합니다.
2. 공공데이터 원본 확보 방법: (a) 전국도서관표준데이터 CSV를 직접 내려받아 전달, 또는 (b) 개발 환경에서 공공데이터 사이트(data.go.kr, data.seoul.go.kr)와 도서관 홈페이지 접속 허용.
3. 특일정보 API 인증키(공공데이터포털 활용 신청) 발급 여부. 키 없이 진행하려면 공휴일 목록을 직접 정리한 JSON으로 대신합니다.
4. 전국도서관표준데이터의 실제 항목 구성과 이용 조건(공공누리 유형)을 원본으로 확인합니다.
5. 카카오맵·네이버 지도 길찾기 링크의 대중교통 탭 동작을 실제 기기로 확인합니다.
6. 기본 지도 중심 위치(예: 구로구청 또는 집 근처)를 정합니다.

## 부록 A. 카카오맵 JavaScript 키 발급 방법 (P2 준비)

1. [Kakao Developers](https://developers.kakao.com)에 카카오 계정으로 로그인하고 개발자로 등록합니다.
2. **내 애플리케이션 → 애플리케이션 추가하기**에서 앱 이름(예: Library Now)을 입력해 만듭니다.
3. **앱 설정 → 앱 키**에서 **JavaScript 키**를 확인합니다.
4. **앱 설정 → 플랫폼 → Web 플랫폼 등록**에서 사이트 도메인을 등록합니다.
   - 개발용: `http://localhost:5173`
   - 배포용: `https://{GitHub 아이디}.github.io`
5. **제품 설정**에서 **카카오맵** 사용 설정을 켭니다(콘솔 메뉴 이름은 바뀔 수 있으니 적용할 때 다시 확인합니다).
6. 발급받은 키를 GitHub 저장소의 Actions 변수(`VITE_KAKAO_JS_KEY`)로 등록하면, 배포 시 앱에 들어갑니다.
   - JavaScript 키는 브라우저에 노출되는 것이 정상이며, 4단계에서 등록한 도메인에서만 동작합니다.
